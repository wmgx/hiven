# Launcher 交互优化设计

## 目标

优化 Global Launcher 的插件交互逻辑，让用户尽量一步到位获取结果，减少不必要的选择层级。

---

## 核心原则

| 原则 | 说明 |
|------|------|
| 命令优先 | Global Launcher 默认走命令形式，不额外开 UI |
| 一步到位 | 剪贴板智能识别 + 命令展开，不要二级选择 |
| 结果写剪贴板 | Global Launcher 执行结果统一写剪贴板 |
| 编辑器不动 | App 内命令保持原地替换的现有交互 |
| UI 是最后手段 | 只有命令满足不了时才走 UI |

---

## 三层交互模型

| 层 | 触发 | 输出位置 | 场景 |
|---|---|---|---|
| **L0 剪贴板智能识别** | Launcher 打开时读剪贴板 | 即时结果 → 写剪贴板 | `eyJhb...` → 推荐 JWT 解码 |
| **L1 命令执行** | Launcher 里搜索/选命令 | 写剪贴板 | 选 "URL 编码" → 结果写剪贴板 |
| **L2 编辑器原地替换** | App 内命令 | 替换当前 pane | 保持现有，不改 |
| **L3 Cmd+Enter 升级** | 命令选中后 Cmd+Enter | 打开插件 UI 并带入内容 | 翻译 → 打开翻译页面 |

---

## 命令展开规则

**一个插件 = 多个 Launcher 命令，每个命令直接执行，不再有子选择。**

| 插件 | 展开命令 | L0 剪贴板智能 | 识别规则 |

| **jwt** | `JWT 解码` | ✅ | `eyJ` 开头 → 推荐解码 |

## L0 剪贴板智能识别逻辑

```
Launcher 打开
  → 读剪贴板内容
  → 并行跑所有插件的识别规则（轻量正则/前缀匹配）
  → 命中单方向：推荐一个动作（如 JWT 解码）
  → 命中双方向且可判断方向：推荐确定方向（如 %E4 → URL 解码）
  → 命中双方向但方向不确定：推荐该插件所有命令（如 CSS → 格式化/压缩都列出）
  → 命中多个插件：全部列出
  → 不命中：正常搜索命令
```

### 用户操作流

```
选中推荐动作 → 执行 → 结果写剪贴板 → Launcher 关闭（或展示确认）
```

## Global Launcher vs 编辑器内的区别

| 维度 | Global Launcher | 编辑器内命令 |
|---|---|---|
| 输入来源 | 剪贴板 | 当前 pane 文本 |
| 输出位置 | 写剪贴板 | 原地替换 pane |
| L0 智能识别 | ✅ 有 | ❌ 无（用户已选中内容） |
| Cmd+Enter 升级 | ✅ 有（打开 UI） | ❌ 不需要 |
| 命令展开 | 同一套命令列表 | 同一套命令列表 |

## translate 特殊处理

| 场景 | 行为 |
|---|---|
| 剪贴板有内容 + 选中翻译命令 | L0 即时翻译，结果写剪贴板 |
| 用户有输入需求（想改原文） | 走 UI，打开翻译页面 |
| Cmd+Enter | 打开翻译页面并带入剪贴板内容 |

translate 的 L0 即时翻译只支持剪贴板内容作为输入源，不支持在 Launcher 里手动输入文本进行翻译。

## 设计决策记录

1. **base64 不做 UI** — 重构时做的 UI 去掉，保持命令形式
2. **所有有方向/模式选择的拆成独立命令** — 一步到位，不要二级选择
3. **Global Launcher 结果统一写剪贴板** — 不在 Launcher 里做结果展示区
4. **CSV UI 后面单独做** — 本次只提供 `CSV → JSON` / `JSON → CSV` 命令
5. **textDiff 后面单独优化** — 打开编辑器 diff 面板，不在本次范围
