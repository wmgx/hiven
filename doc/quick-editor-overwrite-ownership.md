# QuickEditor 外部覆盖与草稿归档

2026-10-11。修复真实原生审查发现的问题：独立 QuickEditor 中编辑的最新草稿被外部内容覆盖后，历史为空或只保存 Launcher 的旧版本。

## 归属与提交

桌面外部覆盖由实际独立编辑器处理。发送方只传新正文、语言及来源，不再选择目标 pane 或携带自己的历史列表。独立窗口已存在时读取其当前活动 pane；不存在时先按原入口建窗，由新窗口从现有存储载入草稿。搜索仍可进入内嵌编辑器，快捷键仍使用独立窗口，不改变入口形态。

接收器就绪探测先于正文交接；请求绑定目标窗口实例、唯一标识和有效期。同一请求只提交一次，重复消息只重放回执；旧窗口或过期消息不会覆盖新草稿。只有归档与替换完成持久化后才回成功结果。回执丢失时不盲目自动重写；原草稿仍在已提交的历史中，调用方提示先查看再重试。

覆盖与恢复沿用 `hiven-quick-editor`、现有历史结构及数量上限。先同步写入包含原草稿全文的完整下一状态，再发布内存状态，避免 Zustand 默认“先改内存后存储”的失败窗口。存储未成功载入或写入失败时拒绝替换。恢复版本由当前持有者本地完成，不再广播发送方历史覆盖其它窗口。

独立窗口关闭后，搜索重新进入内嵌编辑器及新增 pane 入口先刷新已保存状态，防止驻留 Launcher 的旧内存重新成为草稿来源。没有新增存储系统、通用工作流或插件权限。

## 验证

使用 Linux X11 原生 AppImage、隔离 profile、合成文本及实际键盘和 WebKit WebDriver：

1. 独立窗口输入多行 A，外部文本 B 写入后从 History 恢复 A；从编辑器实际复制核对全文，包括换行和末尾空格。
2. 恢复后编辑成多行 C，运行已有 Base64 Decode，将结果返回 Launcher 并写入 QuickEditor；从 History 恢复 C，再次复制核对全文。
3. 关闭独立窗口，经搜索返回内嵌编辑器，仍为最新 C。
4. 此时无独立窗口，再次外部写入触发新建窗口；C 被正确归档并可完整恢复。
5. 仅在隔离目标窗口注入一次 `Storage.setItem` 合成配额异常。调用方收到失败结果，目标正文及已保存历史与操作前相同；随后撤除注入。这是受控故障验证，不声称制造了实际磁盘耗尽。

针对性逻辑测试使用实际 Zustand store 与模拟窗口事件，覆盖完整归档/恢复、读取/写入失败、接收器就绪、重复请求、窗口替换、过期请求与丢回执后可恢复性。类型检查、架构检查、差异检查、前端和原生构建通过。未为样式编写测试，未调用真实 AI API，未访问用户密钥。

未验证 macOS、Windows、Wayland、进程在同步持久写入期间被强制终止的系统行为，以及完整多 pane 交叉工具回归。原有历史数量上限仍然适用。
