# 文本工具主动离开确认

## 真实问题与范围

2026-10-10，在 `eeb262a` 的 Linux X11 隔离 QA 中，URL 编解码工作台载入 60 字符合成 JSON 材料。用户将工具输入改为 22 字符新稿后点击返回，未出现确认；重新进入时恢复原来的 60 字符材料，工具内新稿不再存在。原材料没有丢失，问题是局部编辑在主动退出时缺少明确的放弃选择。

文本整理、编解码和格式化工作台具有同一种本地输入状态与主动返回合同。本批沿用已发布的宿主布尔状态接口及统一确认，不新增插件退出回调、正文存储或草稿库。

## 行为

- 输入正文相对当前工作台首次载入值发生变化时报告未保存改动，包括手动输入、清空和明确将输出替换输入。
- 自动计算输出、切换工具参数或操作模式不单独触发确认；正文改回载入值后恢复直接返回。
- 同一工作台的普通宿主对象重建不重置基线；新目标经已有 renderer 的 loading 分支卸载旧组件，再以新材料建立基线。
- 主动返回、Esc 和工具关闭复用宿主确认。继续编辑保留当前页面；放弃由宿主执行原导航。
- 成功复制、粘贴成功及已确认的带回搜索仍使用原交付合同。仅已复制而未插入、复制失败或交接失败不清除输入修改状态。

CSV 的导入与查询状态、Diff 的绑定编辑器写入不是同一草稿合同，不在本批接入。也不承诺后台超时、原生窗口销毁或进程退出时保存草稿。
