# 不可用固定项的管理

设置 → 快捷键中的“固定项”提供默认折叠的管理区，包含仍保留的固定记录。入口不再出现在搜索中时，用户仍可明确取消固定；不自动清理记录，也不把失效行加入正常空搜索列表。管理行只能取消固定，不提供执行动作。

展开或刷新时重新扫描完整应用目录，使用原始应用 ID 精确匹配，不根据搜索命中、别名或同名去重判断。扫描中、扫描失败和无法确认都有独立说明；成功缺项只表述为“本次应用扫描未找到”，不推断应用已经卸载。刷新、折叠和卸载同步使旧请求失效，晚回执不能覆盖新状态。其他类型入口不借用应用扫描结论。

新固定的应用仅额外保存经过校验的短名称，不保存路径、正文或动态内容标题。旧记录缺少名称且当前无法解析时明确显示未知固定项，不从 ID 猜名称。稳定固定键保持原结构。取消固定同步清除名称；其他窗口保存设置不会恢复已经取消的键或名称，写入失败保持原状态并允许重试。

取消固定后焦点回到管理区刷新按钮，避免下一次 Enter 落在相邻记录。设置页不参与启动器的 Enter、数字快捷执行，管理记录也不加入启动器候选列表。

## 验证

隔离 Linux 原生 profile 中仅使用自己创建的合成桌面入口：

- 固定后修改中文别名，别名仍找到同一固定项；空搜索没有重复项。
- 暂移入口并刷新，在管理区看到名称及本次扫描未找到的说明；Enter 和数字快捷键没有执行合成启动脚本。
- 明确取消固定后，恢复同一入口仍是未固定；取消后焦点在刷新按钮。
- 另一次暂移不取消，恢复并刷新后仍为固定。
- 结束删除合成入口、清除合成别名，固定键与名称恢复原值。

重要逻辑检查覆盖旧记录、安全名称、跨窗口写入及失败回滚、完整应用 ID、同名不同应用、加载与失败不能判定缺失。类型、架构、前端与原生构建通过。异步失效经独立代码复核，未通过原生 UI 注入扫描失败或迟到回执；macOS、Windows 未进行原生交互验收。未调用真实 API、卸载真实应用或读取真实用户数据。
