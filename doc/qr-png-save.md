# 二维码图片的显式保存

二维码原下载位置改为「保存图片…」，通过公共私有 blob API 调用原生保存对话框。插件只提交自身 blob ID 和建议文件名，不能提交外部目标路径。只有实际写入完成才报告已保存；取消不写文件、不报告成功，原二维码输入保留。

原生先验证所属命名空间并冻结 PNG 字节，限制元数据、编码字节、解码内存、尺寸与像素数量；正常保存对话框选择目标后返回同 webview 的一次性 ticket。宿主复核当前插件注册、来源、权限和 surface 会话，再提交写入；撤权后重新授予也不能复活旧请求。ticket 有数量/时间限制，窗口销毁释放，写入采用临时文件完成后替换。commit 接受之后的真实写盘结果不能因为随后关闭或撤权被改称失败，也不能承诺撤销已写出的文件。

保存能力限定原生桌面，浏览器 relay 不开放这些命令，不通过 anchor 下载回退伪装成功。原图片复制与 DOM 粘贴识别链未在本批修复；可靠验收路径为保存 PNG 后用工具现有文件选择器识别。Base64 按钮准确改称图片 Data URL，粘贴提示区分平台。

## 验证边界

合成事务检查覆盖取消、prepare/commit 失败、撤权再授、注册替换、来源切换、会话关闭重开、focus lease 清理以及提交后的实际结果。真实 PNG 生成经过保存 helper 并由现有 jsQR 解码回同一公开合成文本。权限约定属于可信插件宿主 API，不是针对同进程任意恶意代码的沙箱。

原生聚焦测试八项通过，包含实际临时目录原子写入、失败保旧文件、PNG 上限与校验、ticket 生命周期及 relay 拒绝。最终 npm 入口、插件释放、类型与前端构建通过。`8dec520` 实际 Linux X11 GUI：取消保存保留正文与二维码且不显示已保存；指定新的 QA PNG 后实际报告保存成功；现有文件选择器看到约 1.3 KiB 图片并识别精确 `Hiven QA123`，稳定态同时显示图像。没有用剪贴板图片链替代文件识别。

默认目录后续窄补 `00c5bc4` 选择已有 Pictures、Downloads 或 Home，不继承 AppDir 工作目录、不创建目录。该版 native 编译成功，第一次 linuxdeploy 打包失败且旧日志不足以定因；一次正常官方 bundle-only 恢复 exit 0，未重复编译。新实例实际默认到 QA Home，取消后正文/图像完整、没有新文件或假成功。

纯浏览器可能显示通用保存失败，本批只保证原生桌面路径；没有验证全部平台覆盖提示、覆盖已有文件 GUI 或图片剪贴板读回。
