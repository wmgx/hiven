# JSON 工作台结果带回搜索

## 行为

JSON / YAML 工作台在原有结果动作栏增加“带回搜索”。当前有效结果按普通文本材料交给已有 Launcher 交接接口，不写系统剪贴板，不自动运行下一工具，也不推断结果一定是 JSON。

原有替换输入、复制、返回和关闭含义保持。表达式仍需手动执行；输入或表达式变化后旧结果不能带回。合法的 `0`、`false` 和空字符串结果不会因为 truthy 判断被误拒绝。

交接复用宿主接收确认。未接收或拒绝时保留当前稿件；输入、操作、参数或退出变化同步撤销待交付快照。重复点击不能发出多个交付，Copy 与带回的并发也受隔离。成功导航由宿主负责，插件不额外执行 complete。

## 验证

运行代码本地版本 `100d7c0`，JSON 插件 `2.5.8`。

- 实际 JsonSurface/jsonCore 模块回归覆盖有效输出、表达式失效、取消、失败重试和交错请求；独审另核 Copy 等待期间的新旧 Return、旧请求迟到拒绝不影响新请求。
- typecheck、架构检查、内置插件释放检查与 Vite 构建通过。
- 不修改公共协议、JSON 算法或自动保稿合同；没有执行真实 AI、外部请求或操作用户材料。

## 真实桌面验收

官方 Linux debug AppImage 构建 exit 0，隔离 QA 使用 `100d7c0`，没有重新编译其他分支。

- 正常文件选择器导入含中文、空白、特殊字符、转义引号和换行的 UTF-8 合成 JSON，再在工作台实际把 version 从 old 改为 new。
- 点击 Search 带回结果，URL 组件编码入口收到完整 97 字符当前格式化正文，编码结果为 269 字符；不是原始未修改 JSON。
- 事前通过普通编辑器复制合成哨兵，交接后在新空白编辑器粘贴仍是相同哨兵，确认本次材料交接没有占用系统剪贴板。

- 表达式 `.version` 手动执行得到 new；随后编辑输入时，旧结果清空且带回等输出动作禁用。编辑过程曾产生无效输入，本轮不把它表述为有效新 JSON 的单独 GUI 回归；有效新输入的签名失效由实际模块测试覆盖。
- 英文和中文工作台均通过正常边缘拖动到 664×444（工具内容最小 640×420，另计宿主边距）。三项结果动作保持单行、未裁切、没有新增横带。实际 Shift+Tab 逐项到 Copy/Search/To input，中文同样可达；逐项 AX 记录和最后焦点截图分别留证。
- 父协调与独立审查亲看当前结果交接、剪贴板哨兵、表达式变化及中英文最小宽度截图。

## 边界

真实桌面仅 Linux X11 的 Launcher 工作台入口；独立插件窗口、Windows/macOS 未重复验收。异步拒绝/取消/旧回调使用受控实际模块测试，不冒充真实系统故障。中文通过正常文件选择器导入，再用键盘修改字段；未安装或验证中文 IME。没有修改 Back/Close 退出后的草稿恢复合同，也没有解决已封存的 Quick Editor 崩溃。截图与运行日志仅留内部 QA，不进入公开代码提交。
