# 反方攻击：作为普通开发者，我为什么不会装 Hiven

> 立场：我不是作者。我是一个每天写代码的普通开发者，Mac + VS Code + 终端是我的主场。
> 任务：凶狠攻击《Hiven 探索结论报告》的用户假设，但不许稻草人——报告扎实的地方我会认。
> 证据等级：亲手跑过/公开可查的数据；读仓库代码得出；官方一手资料；
> 待验证；我作为开发者的真实经验判断（已标注，不冒充事实）。

---

## 0. 先说公道话（报告没写错的地方）

1. 0 stars、单作者、假设全未验证——报告自己把这 calibaration 放在第 2 节，这是诚实，不是遮羞。我认。
2. launcher-only 不动、A/B 二选一、feishu 降级、冻结桌面截图监控——都对。截图监控这种想法就不该出现在剪贴板工具的 roadmap 里，砍得对。
3. 技术债部分（门禁红了、lockfile 内网镜像、权限君子协定）是硬货，和产品方向无关，修了就是赚。我认。
4. "AI 负责理解，规则负责执行"是句好原则。

下面开火。**我要打的不是报告的诚实，而是它的用户假设——"开发者每天几十次洗文本，5 步变 3 步，值得每天打开"。**

## 攻击一：频率审计——"每天几十次"是作者的投影，不是我的生活

报告原话："目标用户（开发者/重度文本工作者）每天几十次在'复制—粘贴'之间需要洗一下文本"。

我来做一次 Fermi 拆解，以我自己为样本：

| 任务 | 我的真实频率 | 我现在的解法 | 是否需要"离开当前上下文" |
|---|---|---|---|
| JSON 美化 | 3–5 次/天 | VS Code 里粘贴即格式化（format on paste）/ `jq` | 否，在编辑器里 |
| base64 解码 | ~1 次/周 | `echo xxx \| base64 -d` | 否，终端 |
| 时间戳换算 | ~2 次/月 | 浏览器 devtools / bookmarklet | 很少 |
| URL 编解码 | ~1 次/周 | devtools 里 `encodeURIComponent()` | 否 |
| UUID 生成 | ~2 次/周 | `uuidgen` / 编辑器 snippet | 否 |
| 两段文本 diff | ~2 次/周 | VS Code 内建 diff / `git diff` / `delta` | 否 |
| 行去重排序 | ~1 次/周 | `sort -u` | 否，终端 |
| 翻译报错 | ~3 次/周 | 浏览器划词 / 聊天机器人 | 是，但我要的是翻译质量不是速度 |

**真正"离开当前上下文、需要洗一下文本"的 ≈ 2–5 次/天，不是几十次。** 每次省 5–10 秒，每天可争夺的时间 ≈ 1 分钟。

为每天 1 分钟，装一个常驻托盘应用、让出一个全局热键、给剪贴板读取权限、再培养一套肌肉记忆——这笔账在用户侧根本算不过来。报告把"洗文本"这个动作从它发生的上下文（编辑器/终端/浏览器）里抽象出来计数，犯了**脱离上下文的频率谬误**：文本从来不是在真空中被"洗"的，它永远已经躺在某个工具里，而那个工具 90% 的情况下自带解法。

+（样本是我一人，但这是反方视角允许的；要证伪我，请拿 10 个真实开发者的 diary study 来）

## 攻击二：比较基准是稻草人——对手不是"在线工具网站"

报告的省步表（§3.2/notes/01 §4.2）每一行都在打同一个稻草人："复制→打开在线 JSON 工具网站→粘贴→点 format→复制（5 步）"。**2026 年的开发者谁还这么干？**

真实 incumbent 清单：

- **VS Code 命令面板**：选中 JSON → `⌘⇧P` → "Format Document"，2 步，0 应用切换。它的模糊搜索就是"少搜命令名"的现实版，而且我每天已经按 50 次，形成了肌肉记忆。Hiven 的"热键+Enter"不是在和"5 步"竞争，是在和"我已经会了的 2 步"竞争。
- **Raycast/Alfred（macOS）**：内建计算器（输入即直答，报告的"啊哈时刻 #2"人家出厂就有）、剪贴板历史、Quicklinks（`gh xxx` 这种，报告的"啊哈时刻"之一，人家叫 Quicklinks）。
- **终端单行**：`pbpaste | jq. | pbcopy`、`sort -u`、`uuidgen`。对终端用户，这是 1 步。
- **DevToys（Windows）**：微软生态，30 个工具，Smart Detection 剪贴板感知自动填充——报告自己都承认这是"推荐+填充一体"，Hiven 的感知"只做了一半"。

重算省步（诚实版）：

| 任务 | 报告声称 | 现实 incumbent | Hiven | 真实省步 |
|---|---|---|---|---|
| JSON 美化 | 5→3 | VS Code 2 步 | 3 步 | **-1（更慢）** |
| 时间戳换算 | 4→2 | Raycast 输入即答 2 步 | 2 步 | 0 |
| base64 解码 | 4~5→3 | 终端 1 步 | 3 步 | **-2（更慢）** |
| 开 GitHub 搜索 | 3~4→2 | Raycast Quicklink 2 步 | 2 步 | 0 |
| 生成 UUID | 3→2 | `uuidgen` 1 步 / snippet 2 步 | 2 步 | 0 ~ -1 |

**"5 步变 3 步"是拿 2015 年的上网方式当分母。** 真实世界里 Hiven 很多时候是打平甚至更慢——因为它要求我先把文本"运"到它的 launcher 里，而 incumbent 让我在文本所在之处直接动手。报告引以为傲的"0 切换"，前提是"文本已经在你手里（剪贴板）"；但文本更多时候在编辑器/终端里，那里本来就不需要切换。

## 攻击三：习惯迁移成本——报告没算的三笔账

即使某天 Hiven 真的快 1 步，用户还要付：

**1. 热键位是稀缺不动产。** macOS 上：`⌘Space`（Spotlight/Raycast）、`⌥Space`（Raycast 默认），加上各应用自己的全局键。好按的全局热键就那么几个，全被占了。Hiven 要一个 launcher 热键；方向 2 的"选中即行动"再要一个。**让用户给 0-star 应用让出两个 premium 热键位？** 报告通篇没提热键冲突，只谈"唤起速度"。

**2. 肌肉记忆是最贵的迁移成本。** "复制→热键→Enter"这套 reflex 需要几周才能建成，期间用户会不断误触旧 reflex（`⌘Tab` 切 VS Code）。而收益是每天省 1 分钟（攻击一）。**回报周期以月计，放弃成本为零**——任何一次卡顿、一次更新翻车，用户就回滚到旧习惯。to-do 式的效率工具死在这条曲线上的不计其数。+

**3. 托盘常驻的心理成本。** 菜单栏/tray 是用户最抠门的房地产（Bartender、Ice 这类菜单栏管理工具的存在就是证明）。一个文本工具凭什么常驻？Raycast 常驻因为它是 OS 入口；Hiven 常驻只为了"每天 2–5 次、每次省几秒"。性价比在心理上不成立。

报告算了"省几步"，没算"凭什么让我改变"。**迁移成本不在功能表里，在习惯里。**

## 攻击四：信任成本——一个读剪贴板的 0-star 应用，凭什么

这是最凶的一条，因为报告自己提供了弹药：

1. **权限模型是君子协定**：Rust 侧 `plugin_shell_run`（完整任意命令执行）、`plugin_http_request`**零调用方鉴权**；第三方插件与 host 同 renderer，可直调 invoke 绕过授权、可读别家插件 localStorage 私有数据。翻译一下：任何一个插件作者（未来）都能读我的剪贴板、调 shell。而用户粘贴的恰恰是最敏感的东西——API keys、tokens、生产环境 JSON。
2. **`"csp": null`**、updater 走第三方代理域名、质量门禁红了 20 个 tsc 错误——"quiet, precise, capable"的品牌故事，在工程现实面前是漏的。
3. **0 stars + 无 License + 单作者**：开源不等于被审计过。0 个外部 reviewer 的开源项目，安全上和闭源没有区别，甚至更差（攻击面公开）。
4. **"学习我"的原罪**：即使桌面截图监控被冻结了，"clipboard 配对 + URL 模板"学习还在 roadmap 上。一个**以读取剪贴板为生**的工具，还想挖掘我的剪贴板模式——salted hash 也不行。威胁模型很具体：机器一旦被攻破，攻击者拿到的不只是剪贴板历史，还有"我的 secret 长什么样"的模式库。这是剪贴板工具的**信任模型根本冲突**，不是"分级授权"能洗的。

公道话：本地优先、无云同步、开源，确实是诚实的信任故事。但**信任不是功能，是证据**：签名构建、License、第三方审计、权限最小化（先把 Rust 侧鉴权做了）——这些在报告里是技术债第 2 条，在用户侧是**装机前置条件**。报告把信任当技术问题谈，错了；信任是获客问题。

## 攻击五：获客逻辑缺位——方向 1~5 的 ROI 全是空中楼阁

报告第 2 节承认"任何大投入之前都需要第一个外部真实用户"，然后第 3.2 节照常给方向 1~5 排了 ROI 优先级。**这在逻辑上是断裂的**：ROI = 单用户价值 × 用户数；用户数 = 1（作者）时，任何排序都是在给 deck chairs 排座位。

我替报告补上它没答的三问：

**1. 第一个外部用户从哪里来？**
- macOS 开发者？人家有 Raycast/Alfred。Hiven 的 pitch 是"我们不是全能 launcher"——**这在获客时是劣势**：用户不想装两个 launcher，不想给第二个热键位。
- Windows 开发者？DevToys（微软生态背书）+ PowerToys（文本提取/取色/纯文本粘贴）已经把"瑞士军刀"位占了。Hiven 的"launcher-only"对 fresh user 不是优势，是**功能更少**。
- 中文用户？uTools 的超级面板+插件生态是本土王者。
- 诚实答案：唯一的 beachhead 是作者自己的受众（博客/X）。0 stars + 无营销面，自然获客 ≈ 0。**报告没有获客逻辑。**

**2. 方向 1（accepts 覆盖率）是 retention 特性，不是 acquisition 特性。** "复制→热键→它已经知道你想干什么"这个啊哈时刻，**装完才能体验**。你没法向没装的人演示它。排 ROI 第一的方向，获客贡献为零。

**3. 真正的获客特性长什么样？** 能录成 30 秒视频传播的：语义 JSON diff 一键分享（deeplink，竞品思路 #7）、"选中即行动"的当场 wow。报告把这些放在"可借鉴思路"里吃灰，却把"补 accepts"（用户看不见的工程活）排第一——**这是工程师的 ROI，不是市场的 ROI。**

结论：**P0 不是方向 1~5 中的任何一个，P0 是"让 10 个真实用户装上并留下来"的获客实验。** 在获客逻辑补上之前，方向排序越精致，越是精致的自嗨。

## 攻击六（往死里打）：自学习——0/216 的市场投票，判死刑，不是缓刑

报告对自学习的处理是："做 clipboard 配对 + URL 模板，冻结桌面监控"，理由之一是"08-20 的复盘是健康的自我纠正"。我不同意"健康"，我要判死刑，武器就是报告自己的数据：

**提议卡 P2c：proposal_ready 216 次展示，接受 0 次。**

这是全报告里**唯一的真实用户行为数据**（作者自己的 dogfooding 也是行为），而它的投票结果是：**用户不想要应用替他做决定，一次都不想要。** 报告的解读是"提议卡形态错了，改静默学习+首次发火可见可撤销"。我的解读更凶：**形态不是问题，问题是"被猜中"这件事本身在文本工作流里没有价值。**

为什么：

1. **文本任务是高确定性、低重复度的。** 我今天 base64 解码一段 token，明天格式化一段 JSON——"重复模式"在周级别都罕见。frecency 排序（把常用的往上放）已经吃掉了 90% 的"学习"价值，剩下的 10% 不值得一套规则引擎。
2. **"静默学习+首次发火可见可撤销"比提议卡更吓人。** 提议卡至少诚实（"我猜你要这个"）；静默建规则是应用背着我改了自己的行为，首次发火时我看到的不是惊喜，是**失控感**。"忽略不是终态"——对，终态应该是删除。
3. **URL 模板学习是 creepy 的。** "复制单号→自动打开查询页"听起来 clever，细想：应用在监视我的剪贴板内容并匹配外部跳转模式。今天是单号，明天是什么？这是用便利换监视，和剪贴板工具该有的信任模型（"我只在你叫我时干活"）直接冲突。
4. **机会成本**：`src/workspace/learning/` 3651 行 + telemetry 里 1/3 事件是 `perf:learning.*`——一个被市场 0/216 否决的方向，吃掉了全项目可观的工程投入。继续"做 clipboard 配对"是沉没成本谬误。

**判决**：删除规则学习机制，只保留 frecency/favorite 排序（那叫排序，不叫学习）。把 `learning/` 的维护人力还给方向 1。

+（0/216）

## 必须修改的 3 处结论

**1. ROI 排序的前提错了——补上获客 P0，否则排序无意义。**
原结论"方向 1（内容感知覆盖率）ROI 最高"成立的前提是"用户已经装上了"。必须新增一个高于一切的 P0："获得前 10 个真实用户的获客实验"，并诚实回答 beachhead（大概率是作者个人受众 + 可传播的 wow 特性，如语义 diff 分享 deeplink）。在获客逻辑补上前，方向 1~5 的排序应标注为"留存优化排序，不是指导投入的排序"。

**2. 自学习判死刑，不是缓刑。**
"做 clipboard 配对 + URL 模板"改为"删除规则学习机制，仅保留 frecency/favorite 排序"。0/216 是全报告唯一的真实行为数据，它投的是反对票；salted-hash 剪贴板挖掘与剪贴板工具的信任模型根本冲突。

**3. 省步表的比较基准必须换成真实 incumbent。**
"在线工具网站 5 步"这个分母是 2015 年的。重算基准：VS Code 命令面板、Raycast/Alfred 内建能力、终端单行。重算后 Hiven 的边际收益从"5→3"降级为"3→2.5（经常打平或更慢）"。这直接动摇"值得每天打开"的强度判断——结论应降级为"niche 效率工具"，或找到真正的 10x 时刻（语义 diff + 一键分享可能是，但还没被验证）。
