# 对抗脑暴裁决报告（08-adversarial-verdict）

> 日期：2026-10-11。方法：5 个反方（用户侧 / 产品定位 / 技术现实主义 / AI 激进派 / 市场存在性质疑）独立攻击《Hiven 探索结论报告》+《06-ai-integration》，本报告逐项裁决。
> 裁决等级：**成立**（原结论修改）、**部分成立**（修正表述/范围）、**不成立**（反方未击穿）。
> 对抗文档：notes/07-adversarial-1-user.md ~ 07-adversarial-5-market.md。

---

## 0. 总裁决（一句话）

五个反方从五个方向独立开火，**核心指控一致且成立**：原报告是一份"给成熟产品的路线图"，套在了一个零用户的项目上——它算清了"省几步"，没算"凭什么让我装"；把工程美德排在了获客现实前面；默认了"产品值得继续做"却没回答"为什么需要独立存在"。**原报告约 60% 的判断存活（多为"不做什么"），约 40% 需要修正（多为"优先级与前提"）。**

## 2. 逐项裁决

### 2.1 用户假设：频率、基准、迁移成本（用户侧攻击 1/2/3）→ 成立

- **"每天几十次"是投影**：Fermi 拆解成立——多数"洗文本"发生在上下文内（VS Code/终端），真正需要跨上下文的 ≈ 2–5 次/天。原报告犯了**脱离上下文的频率谬误**。
- **比较基准是稻草人**："在线工具 5 步"是 2015 年的分母；真实 incumbent 是 VS Code 命令面板（2 步）、Raycast 内建、终端单行。重算后 Hiven 经常打平甚至更慢。
- **习惯迁移成本未定价**：热键位稀缺、肌肉记忆昂贵、托盘心理成本——全是真实成本，原报告没算。
- **修正**：删掉"每天几十次"；省步表以真实 incumbent 为分母重算；Hiven 的诚实 pitch 从"步数更少"改为 **"跨上下文的一致性"**——单个场景打不过 incumbent，但"任何地方、同一套 reflex"是 incumbent 给不了的（VS Code 只管编辑器里，终端只管终端里）。这恰好让"剪贴板闭环 + 选区感知"成为真正的战场，而不是"补 accepts"。

### 2.2 信任：从"技术债"升为"获客前置条件"（用户侧攻击 4）→ 成立

- "信任不是功能，是证据；信任是获客问题，不是技术问题"——成立。
- **修正**：把 License 声明、签名构建、信任边界文档化、Rust 侧鉴权从"技术债 #2"移入 **"获客 P0 门"**。但与技术反方调和：**文档化/声明类现在做（便宜），写代码的 Rust 鉴权等插件分发决策**（见 2.7）。

### 2.3 获客 P0：新增第 0 优先级（用户侧攻击 5 / 产品攻击 6 / 市场攻击 3）→ 成立

- 原报告 §2 说"需要第一个外部真实用户"，§3 又照常排 P0——逻辑断裂，成立。
- **修正**：新增 **P0 = 获客/存在性验证**，高于一切方向：
1. 恢复发布（3.5 个月零发布）+ License 声明；
2. "前 10 个真实用户"实验，beachhead 诚实定位为作者个人受众；
3. 方向 1–5 重标注为 **"留存优化排序"**，不得指导投入；
4. 每个方向补**验收标准/杀线**（如"补 10 个 head accepts，推荐接受率 < X 则停"）。
- 市场反方的精确指控成立："停止向市场交付"而非弃坑——持续投入却不敢发布，说明找不到交出去的理由。

### 2.4 自学习：判死刑，不是缓刑（用户侧攻击 6）→ 成立（大部分）

- 0/216（proposal_ready 216 次展示、0 次接受）是全报告唯一的真实行为数据，投的是反对票——成立。
- "静默学习+首次发火"比提议卡更吓人（失控感）、URL 模板挖掘 creepy、与剪贴板工具信任模型冲突——成立。
- **修正**：删除被动规则学习机制（proposal→静默→发火整条链），只保留 frecency/favorite **排序**（那叫排序，不叫学习）；URL 模板改为**用户显式"教一次"**（如 uTools 的用户配置正则，而非挖掘）。把 `learning/` 的维护人力还给 head 意图覆盖。

### 2.5 launcher-only：教条→分工（产品攻击 1）→ 部分成立

- "产品现实已是混合体"（独立窗口、可 detach 编辑器）是事实；"3 步没算校验步"成立；staging 型任务（长日志对照、多次试解码）被系统性亏待——成立。
- 但工作台回摆仍不做（已证伪，不动摇）。
- **修正**：不复活工作台，但把 **Quick Editor 升格为一等暂存面**：launcher 加"一键暂存到编辑器"；staging 型任务默认落编辑器/diff 面板；定位改写为 **"launcher 负责 one-shot，编辑器负责 staging"**，并补上 DESIGN.md 与多 pane 实现的口径（承认或砍掉，二选一）。

### 2.6 A/B 二选一 → 改述（产品攻击 2）→ 成立（改述）

- "没人会为洗文本装 launcher"作为假设成立且举证责任在原报告；"入场券 vs 二等公民"自相矛盾——成立。
- **修正**：**二等的是投入广度，不是质量标准与叙事位置**。App/URL 启动质量必须一等（速度、排序、frecency 零抽风）；叙事翻转对外讲"最快的 launcher，顺手把文本洗了"（获客），对内 A 是留存与差异化。停止"窗口/进程扩张"保留，但"飞书深度集成停止投入"改为待数据（见 2.8）。

### 2.7 accepts 极致化 → head 覆盖 + 可解释性 P0（产品攻击 3）→ 部分成立

- 边际递减数学（省的是"搜两个字母"）、误推荐风险、head/tail 分割、frecency 已覆盖尾部——成立。
- **修正**：方向 1 改写为"**head 意图覆盖（top ~10，用作者 telemetry 定名单）+ 排序可解释性升 P0**"；每个 accepts 声明设**接受率验收线**，低于阈值降级为普通搜索结果；尾部交还 frecency + 别名/拼音搜索。作者可读 `~/.local/hiven/logs/launcher-perf.ndjson` 按意图分桶验证（`object_action.execute` 接受率）。

### 2.8 "选中即行动"：双热键 → 单热键选区感知（产品攻击 4）→ 成立

- 双热键=两次决策成本；Raycast 恰恰没做通用面板（证据注水成立）；跨平台选区抓取是可靠性 minefield——成立。
- **修正**：**不加第二个全局热键**。唯一热键具备选区感知："热键永远作用于当前选中的东西，没有选中才用剪贴板"——一条 crisp 规则，零新概念，拿 80% 收益。省下的精力投给选区抓取可靠性的 telemetry。

### 2.9 feishu：死刑 → 缓刑待数据（产品攻击 5）→ 成立（程序上）

- "没读 telemetry 就判死刑，程序不正义"——成立。数据在作者自己机器上，[`behavior:launcher.item_select`] 可直接回答。
- "中文 IM 生态集成可能是唯一护城河"——列为**待验证假设**，不采纳也不证伪。
- **修正**：feishu 处置冻结，待作者读数：高频 → 立为第二支柱（并降低 lark-cli 配置门槛）；低频 → 那时再默认关闭。

### 2.10 技术债重排（技术反方攻击 1/4/5）→ 成立

- CI 8 次全失败死于 Install（新事实，决定性）；热路径零 tsc 错误；build 不跑 tsc；5 个错误在已冻结的 observation/（原报告自相矛盾，认）；无 pre-commit hook——全成立。
- **修正后的技术路线**：
1. **第 0 项（小时级）**：修 lockfile registry——理由改为**解锁 CI**，不是贡献者；
2. **本周**：门禁瘦身 <30s（typecheck + arch + 约 10 个热路径行为测试）+ 补 pre-commit hook + 删除正则断言源码的脆弱测试；20 个 tsc 错误降级为机械批处理；
3. **永不作为独立任务**：tsconfig strict 迁移、lib.rs 大拆分、"154 测试并入 gate"（方向反了）；
4. **保留**：首屏 chunk 体积（120ms 是用户价值）、热路径行为测试（accepts 覆盖的安全网）、新 surface 的 telemetry 错误事件。

### 2.11 权限与沙箱（技术反方攻击 2/3）→ 成立

- "不为假想敌付税" vs "0.5 人周止血"自相矛盾——成立，**删除该推荐**。
- pluginId 可伪造、JS 唯一调用方是 host 自身、"知情同意完整性≠安全"——成立。
- Obsidian/VS Code/Raycast 无沙箱也有繁荣市场——成立且原报告本该有此论证。
- **修正**：权限加固是**插件分发战略决策的下游**，决策前只做文档化信任边界，一行代码不写；"插件真沙箱"从"证伪"升级为"永久移出路线图"，问题重述为"插件分发的信任模型"，答案是**策展**（签名校验 + 更新权限再确认 + review），不是沙箱。另：沙箱会倒退富插件 UI 能力与热路径延迟——这是人周算不出的战略成本。

### 2.12 AI 框架：从"套缰绳"到"搞定+兜底"（AI 激进派攻击 1/2）→ 部分成立

- "AI 负责搞定，预览负责兜底"**严格优于**原表述"AI 负责理解、规则负责执行"——采纳。preview-then-apply 从"把 AI 贬为顾问的理由"正名为"兜底机制"，原意保留。
- "150ms 神圣不可侵犯"过度泛化——成立。**修正为延迟分档**：隐式/内联（排名推荐）150ms 不动；**显式调用允许 2–5 秒 + 流式**（首 token ~300ms），用户主动选择进慢车道。
- "不开新界面"绝对化——成立（06 文档自认 threaded refinement 即新界面，自相矛盾）。**修正**：hot path 不开新界面；显式调用值得专用 surface（原文+流式+diff+追问的 AI 模式面板可作为 Phase 2+ 设计参考）。
- "精确可预测是前 AI 品牌遗产"—— provocative 但在零用户阶段不改品牌：信任重建（diff+撤销+标记）是机制，可以采纳；品牌叙事等有用户再议。

### 2.13 AI 拥有头部？不反转，但并行（AI 激进派攻击 3）→ 不成立（反转部分）

- "AI commoditize 头部最快"是真，但对 Hiven 现实（零用户、单作者 dogfooding、私有免费即时已建成 directAnswer）而言，"AI 拥有头部"意味着把最高频路径的 token 成本+延迟转嫁给用户，且规则 headline 的边际成本已很小。
- **裁决**：不做反转，但接受"并行"——Phase 0 不再是"做满 rules 再谈 AI"的串行；NL 驱动的一等入口作为**并行实验 track**推进（铁律"确定性回退"本身就允许：AI 可以拥有头部**交互入口**，规则拥有兜底）。待本机 AI 护城河成立、有用户可验证时再议反转。

### 2.14 本机 AI：从"选项"升级为"战略护城河"（AI 激进派攻击 4）→ 部分成立

- "文本不出本机"是 Hiven 对抗 Raycast/浏览器侧栏唯一独占的主张——成立；Boop 靠这句话活到今天——成立。
- "小模型弱点可用本地验证闭环对冲"（正则 tester 天然验证、JSON schema 校验）——成立，原报告漏掉了这个关键论证。
- **修正**：本机模型从"四档之一"升级为**默认推荐的理解引擎（可选下载，不进基础包）**，云端为 fallback；Apple Silicon MLX 是加分项。但 2–4GB 下载与模型选型维护税如实计入成本。

### 2.15 存在性：补上缺失的一环（市场反方攻击 1/2/4/5）→ 成立

- "18 插件 ≈ 两个 Raycast 扩展"事实映射成立；"内容感知是微创新、对手一个版本可抹平"成立；冷启动悖论（2/3 功能无 accepts）成立。
- "答不上来非我不可=没有内核"——作为**独立产品**成立；作为**作者个人工作流**不成立（revealed preference：818 commits）。
- **修正**：原报告 §3.1 必须补**存在性前提 gate**——"为什么是独立产品而不是 Raycast 扩展/uTools 插件/Boop fork"，答不上来就不配谈独立产品路线图。**形态三分野**正式立项（见 §3）：
1. **个人效率工具**（当前 reality）：值得继续；砍掉产品剧场（release 仪式感、英文 i18n 优先级、updater 运营、给不存在的第三方的 SDK 投入）；
2. **被收编**（Raycast 扩展 / uTools 插件）：唯一能让代码产生外部价值的路径，去用户所在的地方；
3. **独立产品豪赌**：需先过存在性 gate + 获客 P0，不推荐盲进。
- "3.5 个月不发布+持续提交=卡在两种形态中间"——成立，这是全篇最有解释力的观察之一。

## 3. 修正后的结论（替代原报告 §3 的执行版）

### 第 0 优先级：存在性与获客（新增，高于一切）
1. 选形态：个人工具 / 被收编 / 独立产品（三选一，写下来）。
2. 若选独立产品：先过存在性 gate（为什么不是 Raycast 扩展/uTools 插件/Boop fork）；恢复发布 + License 声明；"前 10 个真实用户"实验。
3. 信任前置：License、签名构建、信任边界文档化（便宜的先做）。

### 修订后的方向（留存优化排序，不是指导投入的排序）
1. **跨上下文一致性**（原"内容感知覆盖率"的修正版）：head 意图 accepts + 排序可解释性 P0 + 接受率验收线；pitch 从"步数更少"改为"任何地方同一套 reflex"。
2. **单热键选区感知**（原"就地面板"的修正版）：不加第二热键；"热键永远作用于当前选中的东西"。
3. **剪贴板闭环 + Quick Editor 暂存面**：结果即对象、链式、重放；编辑器升格为 staging 面（launcher/one-shot vs 编辑器/staging 分工写进定位）。
4. **AI**：原则改为"AI 负责搞定，预览负责兜底"；延迟分档；本机 AI 为默认推荐理解引擎（可选下载）；NL 一等入口并行实验；正则生成仍是 Phase 1 起点；全局聊天框仍不做。
5. **单文件脚本层**：保留（反方未击穿，且是 transform-by-description 的沉淀目标）。

### 修订后的不做/冻结（新增）
- 被动规则学习机制删除（0/216 死刑），只留 frecency 排序；URL 模板改为用户显式教授。
- feishu：缓刑待作者 telemetry 数据。
- Rust 鉴权代码：等分发决策；沙箱：永久出局，换策展。
- strict 迁移、lib.rs 大拆分：永不作为独立任务。

### 仍存活的原结论（反方未击穿）
launcher-only（one-shot 部分）、三种重构证伪（论证升级）、不做全局 AI 聊天框、observation 冻结、删减清单其余 11 条大体成立、交互 P0（overlay 丢数据）/P1（IME Esc）、120ms 预算、"AI 负责理解…"升级为"搞定+兜底"、preview-then-apply、provenance 标记、observation 数据不进 AI。

## 5. 方法论备注

- 五个反方有 3 处互相印证（获客缺位×3、自学习死刑×2、门禁真相×2），印证处置信度最高。
- 所有级攻击已标注举证责任与证伪判据（如 telemetry 读数），作者是唯一能证伪的人——这正是"第 0 优先级"的含义。
- 本轮没有推翻原报告的诚实部分（0 stars 自曝、UI 零验证声明、技术债硬货）；推翻的是**优先级排序的前提**与**三个过度泛化的判断**（频率、基准、AI 保守框架的绝对化表述）。
