# 单个短倒计时

时间助手 1.11.0 增加显式入口，例如 `10分钟倒计时`、`countdown 10 minutes`，支持整数 1 秒至 60 分钟。搜索只展示动作，执行才开始。既有“10分钟后”与 cron 仍只计算、复制时间，不创建计时。

当前仅支持 Linux 原生桌面。使用 `CLOCK_BOOTTIME` 的经过时间，包含系统休眠，不读取墙钟作为到期依据；修改系统日期/时间不改变剩余时长。休眠期间不唤醒设备，恢复运行后下一次核对才处理到期。其他平台及浏览器入口明确不可用，不回退到语义不可靠的 WebView 定时器。

一次只有一个运行中的计时。重复开始会显示已有状态，不静默替换。搜索“倒计时”或 `countdown`，执行“短倒计时”可查看原生剩余时间快照、刷新、取消及返回工作。刷新复用当前结果层，返回不会露出旧快照；终态也有明确结果行，不触发单项自动执行。取消携带原计时身份，旧结果和晚请求不能取消新计时。

原生应用持有状态，隐藏 Launcher 不影响运行。仅运行期间每 200ms 核对到期，空闲/终态由 Notify 等待，不持续轮询 UI。持久文件 `short-countdown.json` 只含格式版本、随机身份、秒数、阶段，不保存查询正文、绝对期限、应用目标或用户数据。开始、取消和到期先写临时文件、同步并原子替换，再确认状态；文件损坏或保存失败不会被当作成功或空状态。到期保存失败时保留原状态并重试，查询明确显示保存错误。仅保留最近一次状态，用户明确开始下一次后取代它。

正常退出将运行态记为“已中断”；异常退出遗留的运行态也在下次启动恢复成“已中断”。绝不跨进程恢复旧截止点。已落盘的到期/取消终态保持原样；若在到期落盘前进程结束，则保守显示中断，不声称曾提醒。关机或应用未运行期间不会提醒。

到期记录与 HUD 完全独立。固定文案 HUD 读取当前主题/语言，无计时正文，沿用不抢焦点、点击穿透及短期显示规则。只在确认外部应用位于前台时尝试显示，已有失败卡、锁屏或无法确认前台等情况可能抑制提示；不重播、不视作用户已读，最近到期状态始终可回入口查询。没有长期保存原应用窗口的目标屏票据，使用现有鼠标屏/主屏回退。启动新计时后，旧到期回执不能再次显示。HUD 序号保护墙钟回拨，显示时长另有单调时钟上限。

产品入口和文案在时间助手插件。应用组合层只给经 bundled 身份验证的两个指定入口提供受限交接；开始只授予明确启动项，且前后核对 Launcher 会话与插件生命周期。原生命令限制 Launcher，开始/取消还需其可见且聚焦。没有通用调度 API、系统自动化、系统通知权限、全局快捷键或新面板。唯一通用协议补充是结果页显式 `replaceCurrent`，仅替换已有顶层结果，不改变默认追加和单项执行语义。

## 2026-10-13 验收

隔离 Linux X11 profile、合成计时与合成外部文本：

- 搜索“10分钟倒计时”只出现 600 秒开始项，没有启动。真实点击 4 秒开始，回外部窗口持续输入，实际等待到期；固定 HUD 可读、不抢焦点，到期状态已落盘。
- 回原入口查看“已到期”，反复刷新不增加旧结果层。实际取消 8 秒计时后回外部持续输入，并等待超过原期限，无晚到 HUD，状态仍为已取消。
- 30 秒计时运行时执行 20 秒开始项，明确显示已有计时，身份与时长未变。取消后可以再次开始。
- 运行期间终止隔离进程再启动，真实 UI 显示已中断。另通过应用既有允许的 `plugin:process|restart` 执行原生重启，确认落盘中断并重新打开 UI 查看，没有续跑。未以强杀测试冒充正常重启路径。
- 明确归类为受控原生请求：给新计时发送旧计时 ID 的取消请求，新计时保持运行。
- 实际保持 Launcher 在前台等到到期，HUD 未显示；刷新仍显示已到期，证明记录不依赖 HUD 投递。
- 已确认隔离释放目录实际加载时间助手 1.11.0。未启用历史记录、读写剪贴板、使用真实 API/密钥/用户数据或操作 Mac。

真实等待、重启与以上受控请求分开记录。休眠时间跳跃、取消后晚 tick、保存失败和身份替换由独立状态逻辑检查覆盖；未实际挂起机器、锁屏、改变系统时钟或制造断电。Windows/macOS 未实现可靠时钟路径，因此不宣称支持。前端和原生构建、架构与 diff 检查、控制器结果刷新、时间助手既有计算及受限交接检查通过；独立产品/逻辑审查通过。
