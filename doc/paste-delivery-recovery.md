# 粘贴失败恢复与成功交付边界

## 问题和行为

自动粘贴先隐藏来源窗口，再向原前台目标插入。原目标失效时，剪贴板可能已经写入，但原实现把 `copied` 当成完成：Launcher 会清掉当前材料，历史窗口会清掉查询和选中项，失败提示也随隐藏不可见。

本次只有实际插入成功才消费当前工作。写剪贴板成功但插入失败时，仍属于当前尝试的原窗口恢复，保留材料、预览或历史选择，提示已复制但未插入，可手动粘贴。剪贴板写入失败不声称已复制，不自动重试。

## 实现范围

- 每次尝试绑定原窗口实例和业务代际；真正关闭、重开、切换材料或页面、插件失效会撤销。迟到结果不能清除新稿或恢复新窗口。
- 临时隐藏只豁免一次预期失焦。恢复使用原窗口句柄，不调用会重新捕获外部目标的普通打开入口。独立历史窗口的临时隐藏不触发隐藏销毁链，既有定时销毁也校验窗口实例。
- 文本、图片与文件路径输出共用私有尝试生命周期；异步读取、图片构造和动态导入后复核取消。已经完成的外部剪贴板写入或按键不能撤销。
- 通用 Launcher API、预览、当前材料、工作流输出路由以及五个现有工具的 `copied` 分支均按未交付处理。未扩展公共插件结果类型，未新增工作流能力。
- 成功先更新输出记录，再由原调用方关闭。回归包含旧提前关闭控制组，证明不能先重置 controller 再记 LastRun。
- 当前材料的失败复用 Launcher 原错误区，历史的失败复用原 footer，可停留阅读；新查询、材料/选择或下一次动作清理，不覆盖后来的真实 controller 错误。
- Linux X11 保留已有目标身份、串行注入及按键释放保护。macOS 对外部目标交接超时和稳定等待后的目标变化返回失败；未扩展平台目标模型。

## 已完成的受控验证

- 真实 store、paste recovery、paste API、controller 和 LastRun 串联：成功完成记录后关闭；copied 保留原结果且无成功记录；晚失败不污染新流程。
- 原生 owner/X11 定向测试 17 项通过；异步两次尝试互换、取消后的文本/图片导入、renderer 与 beforeOpen 旧句柄、预期失焦及业务失效覆盖通过。
- 实际历史处理回调验证：只有成功才重置浏览、记录使用和 complete；copied/写入失败/取消保留当前浏览状态。
- 最新前端 typecheck、架构、内置插件释放与生产构建通过。原有 `test-clipboard-history-surface-paste-story` 在稳定基线同样因固定依赖数组的源码匹配失败，本次未将其当行为证据；新回归执行真实回调。
