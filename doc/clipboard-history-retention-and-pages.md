# 剪贴板历史：分页、保留和恢复

## 生命周期

取消历史条数与总缓存容量驱动删除，改为 1–12 个 UTC 日历月，默认 3 个月。减月保持 UTC 时分秒，目标月不足原日期时钳制到月末；不是固定 30 天，也不因系统时区或 DST 切换改变边界。单条文本／图片采集大小限制仍生效。

新记录按最后复制时间过期，固定记录不自动过期。旧库权威索引中的记录迁移后全部带 legacy 保护标记，旧 maxItems、retentionDays、maxTotalCacheBytes 不再参与清理。用户在产品内明确纳入旧记录前，不得通过年龄或容量规则绕过保护；纳入时从启用时刻重新计算完整保留期，不立即删除已有老记录。

自动过期只将记录移到回收区，原文和图片保持可读，30 天内可恢复。恢复保持真实复制时间，单独重置保留起点。回收期从实际移入时刻开始，到期再自动永久删除。用户主动删除也进入同样恢复周期，包括主动删除的固定或旧保护记录；它们仅豁免自动过期，不豁免显式手动删除。恢复撤销该删除计划。

后台在启动、每分钟、重新获焦及新增后进行有界维护，独立于「记录剪贴板」开关；停止后台会取消在途批次。应用关闭期间不运行，重新打开后分批追赶；不是保证精确到秒的系统任务。每次扫描 64 条、最多连续 8 批，永久回收每批最多 32 条，失败保留待重试。

## 迁移和事务

旧 `history/index` 是 membership 权威，不能直接枚举 `history/items/` 后让未提交的孤立正文复活。通用宿主 `kv.arrayPage` 使用 SQLite `json_each` 分页读取旧索引，每批最多 8 项；JS 不获取完整数组。完整正文继续使用既有 `history/items/<id>`，不复制或压缩正文。

每批在一个原生 `kv.batch` 事务内提交新排序／hash／图片引用索引和持久迁移 cursor。state CAS revision 是多窗口仲裁点，不依赖单个 webview 的 Promise 锁。故障不推进 cursor；重启可继续，缺失或损坏正文明确停止并保留旧源，不以缺失条目冒充成功。未知版本拒绝迁移，不能删除旧源。

完整迁移持久化 `phase: complete` 后才退役 v1 index；即使删除旧索引失败，下次只重试退役，绝不重新导入。既有 item 正文是唯一规范副本，因此永久清理 v2 时不存在旧索引复活同记录的问题。迁移未完成不允许 GC。

## 有界读取和一致性

排序键使用复制时间／ID，常用排序另建 pasteCount／lastPastedAt 索引。单页最多 100 匹配条目，每次最多扫描 512 元数据；查询可以得到 0 匹配而仍带 continuation cursor。全文搜索逐条读取完整文本用于匹配，不把全部正文缓存进 UI；结果仍返回轻量元数据。UI 使用当前页和 cursor 栈，不无限累积条目。

分页是 live seek cursor，不冻结整个历史快照；期间新写入可在刷新后出现。取消信号使旧查询停止。跨搜索选择通过 `getFreshListItems(selectedIds)` 核对最多 20 个明确 ID，不拿第一页面当全库。普通 `getItem` 只读取活跃记录，回收区预览使用独立 `getTrashItem`，已删除记录不能穿透进复制／Diff／队列。

## 图片安全

原图与预览相同 ID 去重计数；每条记录独立持有图片引用，活跃区和回收区都计入。永久删除先事务移除记录并降低引用数，只有最后引用消失时才建立 GC tombstone。新引用禁止获取已进入 GC 的 ID；恢复与删除共享 CAS，所以多窗口竞态不能在恢复成功后删除图片。物理删除在事务提交后执行，失败留下 GC 队列重试，宁可暂占空间，不先删图后丢记录。

同一图片再次采集会产生新的临时 blob。去重成功事务保留原有图片快照，仅将本次传入且确认零引用的新原图／预览 ID 加入 GC；原图和预览同 ID 去重，活跃区或回收区的共享引用继续保护。事务失败不发布 GC，物理删除失败沿原队列重试。

仅处理已知关联引用或本次明确传入的未使用采集 blob；旧库中未进入权威索引的孤立数据不会被扫描或自动清理。

## 缩短确认方案撤回

`3138d58` 曾为缩短确认引入全体插件设置强制依赖 Web Locks 的提交机制。Linux 两窗口验证不能保证项目全部最低目标运行时具备此能力；缺失时连普通开关、扩大保留期及设置迁移都会被拒绝。因此定点回退该提交，恢复先前普通设置行为，保留无关功能与用户数据。现有原生锁不管理设置 localStorage，Launcher bridge 也不是设置提交协议；可靠替代需要另行设计，未用无锁 fallback 或提高系统门槛规避。

缩短确认目前**未完成、未提供**；旧版跨窗口竞争及持久化前通知订阅者的限制仍在，不能声称已经获得原子提交或 commit-before-publish 保证。类型、原有设置逻辑测试（无 navigator.locks）、架构、前端与原生构建通过。隔离 Linux 桌面确认普通设置 3→4 保存、关闭重开保留 4，再恢复 3；录制始终关闭，完整设置记录恢复原值，没有导入真实历史或执行永久清理。未修改系统设置、最低系统版本或安全权限。

## 局部保留期确认

在撤回全局方案后，仅给 History 的保留月数字段增加可选缩短确认。数字字段由插件声明文案，原 schema/权限/字段定位继续复用。缩短先暂存，确认前不调用保存；扩大复用原保存。取消、关闭设置、切换 owner/定义、隐藏或销毁页面会撤销候选，旧确认回调失效，不回写旧快照。

候选建立与确认前读取现有持久化记录，包含同插件全部字段及版本；读取失败拒绝本次提交，基线变化刷新并要求重新选择。确认通过后从新读取的值构建字段修改，同步走原 setter。这是提交前冲突检测，不是跨窗口原子 CAS：检查后竞争、原 store 通知订阅者早于持久化的顺序、保存失败时后台可能观察过已确认值，均未改变。错误提示只要求核对当前设置，不承诺历史从未受影响。程序化写入、reset、迁移未加全局拦截；当前 History 未提供这些保留期编辑入口。

独立审查及只读快照逻辑测试通过，普通设置 store 未改动。隔离 Linux 原生 UI 验证缩短取消/确认、扩大、关闭重开、连续重新选择，以及另一窗口更新使旧确认失效；另以明确的读/写故障注入验证读取失败拒绝和保存失败提示及重新选择重试。实际关窗为隐藏时发现候选留存，已补局部 visibility/pagehide 撤销并通过真实隐藏/重开复验，同时验证普通数字字段仍直接保存。类型、架构、前端与原生构建通过。录制始终关闭，未导入真实历史、未执行永久清理，最终恢复 3 个月。未引入 Web Locks、原生提交协议或更改最低系统要求；macOS/Windows UI 未实测，不宣称全局互斥。
