# 敏感信号与材料格式分离

## 问题与复用来源

真实纯模块检查使用固定假样本 `password=synthetic-demo-not-a-secret`，其材料原本会遮罩且不把正文交给推荐管线。将同一假值放进 JSON 后，内容检测同时返回 JSON（0.98）和 secret-like（0.9）；主线按最高置信度选择格式，材料只检查所选 kind，因而漏掉遮罩并将正文交给推荐。

独立文件分类实验的 `0045742` 已覆盖同类 JSON/URL 信号优先问题。本批复用其“先检查已有敏感信号”的原则，不合并该实验的文件分类或历史界面变化，不扩充敏感词、命令检测或权限。

## 范围

材料预览遮罩及推荐资格应使用既有敏感信号，不因为同时具有 JSON 等格式而失效。明确的格式标签与原路径分类合同保留。

遮罩不是加密、删除或阻止所有外发。它不改变剪贴板历史原本允许保存、预览和交付未带系统敏感标记文本的合同，也不替代系统剪贴板隐私能力。正文仍由现有材料拥有，用户明确进入本地编辑或工具的合同不在本批重做。

全程只使用固定假样本，不读取真实历史或密钥，不启用采集、不调用 AI 或网络。

## 验证

代码版本 `3718cd0`。生产改动限材料统一构造和 attach policy 两个文件。统一构造从原检测结果中读取敏感信号并设置独立 `secretMasked`，不改变调用方的 kind、完整 payload 或显式 fresh/snapshot 状态。现有 token 遮罩和推荐正文门控继续消费同一标志。

新测试直接加载实际内容检测、snapshot、attach policy、材料构造、当前文本资格和推荐模块。改前 JSON 遮罩断言为红，改后 36 个构造场景及普通路径/推荐隔离/显式本地打开合同通过，独立审查复验通过。样本全部固定且虚构，没有访问实际历史存储。

9 个已有测试只补实际 detector 的依赖绑定，没有弱化断言。共运行 15 项针对脚本，13 项通过；`test-clipboard-direction-adjustment` 的旧 `emptyClipboardBlock` 静态断言，以及 `test-current-text-delivery` 的 `./pasteRecovery` mock 依赖缺失，在原 HEAD 脚本与原生产源的基线对照中也失败，不记为本批通过，也未改无关合同。
