# 文本工作台单步撤销接续

“使用结果继续处理”会替换输入。原先既无中间输入快照，也无工具内恢复入口；顶部返回只提供离开确认，带回搜索则携带当前结果离开。Linux 原生验收中，Ctrl+Z 对接续替换和普通手工输入均未恢复，原因尚未定位。本次不声称修复原生撤销。

每次显式使用结果前，在当前工作台实例内保存一份完整输入、操作、参数和接续后的文本。下一次接续覆盖它；撤销同步消费它，并恢复焦点；卸载工作台释放它。无持久化、历史步骤、自动重放或工作流能力。

仅在有快照时显示“撤销上次接续”。若输入与接续后的文本不同，在原底部操作区请求确认，原结果状态区说明会覆盖手工稿。取消保留当前输入和快照；再次编辑、改参数或退出使旧确认失效。明确确认后恢复完整快照。

恢复复用原 update 路径，使结果 revision 和交付反馈失效；已发出的剪贴板/粘贴交付结算前禁止撤销，避免并发写入。计算本身仍是同步纯转换。插件版本为 3.4.1，内置索引为 123。

原生验收曾发现跨分类恢复时，公共 Select 依赖的选项注册过程会回退旧初始值。工作台操作 Select 现按 category 重建，隔离不同分类的选项注册生命周期；未扩改公共组件。

最终 Linux AppImage 隔离 profile 验收通过：URL 解码接续→清理去重接续→修改全部清理参数并切换 URL 分类→撤销，逐字恢复 38 字符的完整输入（含空格、空行、重复行），恢复清理操作及三个开启参数，焦点回输入，撤销入口消失。再次接续后手工编辑，取消覆盖保稿；确认期间再编辑使旧确认失效，重新确认后恢复且消费快照。重新处理并显式复制，再粘贴到外部编辑器逐字核对 23 字符全文。带着新快照完成交付后重入，输入为空且无撤销入口。

类型、工作台模型、交付反馈/owner 逻辑、插件释放、架构、前端与原生构建通过，独立审查通过。原生加载最终前端资源及 3.4.1 插件已确认。未调用真实 API，未使用真实历史。晚回执保护由既有逻辑测试与独立代码审查覆盖，未伪称做了原生延迟注入验收。Windows/macOS 与普通 Ctrl+Z 平台问题不在已验证范围。
