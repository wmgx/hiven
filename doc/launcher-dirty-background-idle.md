# Launcher 未处理草稿与后台回收

## 实际问题

2026-10-10，代码 `0d4553e` 的 Linux X11 隔离 QA 中，在 URL 工作台输入 22 字符合成新稿，正常切换至合成 Mousepad 窗口。11:24:44 UTC 切离后没有继续操作桌面。

11:29:25 的只读窗口观察确认 Hiven 仍在且失焦；11:29:59 时原窗口已隐藏。隐藏发生在这两次观测之间，不能把其中某一时刻写成精确关闭时间。11:30:17 正常热键唤回后是空搜索页；再次打开 URL，输入与输出均为 0。原工具新稿没有恢复，也没有出现放弃确认。

原因是 Launcher 的连续后台五分钟回收直接调用会话清理。工具的 `closeOnBlur:false` 允许短暂切换应用，却不阻止这个定时清理；主动 Back/Esc/工具关闭的 dirty 确认没有覆盖它。

## 最小控制范围

只在当前 Launcher 插件工作台确有未处理正文修改时暂停这一后台回收计时。草稿仍仅存在于当前组件内存，不新增历史、正文存储、原生接口或后台提示，也不抢回前台焦点。

状态使用当前 target 与 renderer owner 身份，旧页面的清理不能解除新页面的保护。变为干净状态后，若仍处于后台，从当下重新计算完整五分钟；回到前台不计时。明确放弃及成功交付继续沿原关闭合同，粘贴临时隐藏与原生文件对话框的保护独立保留。

此调整不承诺进程退出、崩溃或原生窗口销毁后的恢复，不覆盖独立插件窗口或 QuickEditor 自身存储，也不改变其他主动退出入口。
