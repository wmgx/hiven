# 自动粘贴可用性

自动粘贴前先查询当前原生宿主。查询不读取或写入剪贴板，不隐藏窗口，也不弹出权限申请。

- Linux 的明确 X11 会话：连接 X server 并确认 XTest 和 EWMH 支持后可以尝试。打开 Launcher 或独立工具前记住目标窗口，粘贴前恢复并再次确认该窗口及其输入焦点；目标消失、会话已替换、焦点无法恢复或按键持续按住时拒绝。
- Linux Wayland、未知会话或缺少上述 X11 能力：当前实现不支持自动粘贴。不会借 XWayland 宣称原生 Wayland 支持。
- macOS：只读取现有辅助功能授权；未授权时提示去系统设置授权，或使用复制。
- Windows、已授权的 macOS：可以尝试，仍可能因目标应用、焦点或运行时权限变化失败。
- 旧原生宿主、无法连接或查询超时：状态未知，保留原来的执行路径。

已知不支持或缺少授权时，文本、图片和文件路径的粘贴 API 都在写入剪贴板、读取图片 blob、关闭窗口之前返回 `fallback: 'none'`。调用方保留当前内容，用户可以明确选择复制。Launcher 和工作流适配器会传播此失败，不能记录成成功交付。

Launcher 的文本结果和输入预览在实际提供自动粘贴目标时显示状态。打开目标条、重新聚焦或重新显示窗口会重新检查；真正执行仍重新查询。不能从插件权限声明推断操作系统已授权，也不能把一次查询当作粘贴成功保证。

如果已经开始真实粘贴并成功写入剪贴板，随后输入模拟失败，仍沿用原来的 `fallback: 'copied'` 行为。该情况与执行前拒绝不同；不能据此承诺已经关闭的窗口会恢复，或已发生的外部操作可撤销。

Linux X11 使用正常窗口管理器激活请求，不强制设置任意输入焦点。合成快捷键前等待用户释放按键，并只释放本次合成的键；发送成功只表示 X server 接受事件，仍需目标应用实际接收验收。

从 Launcher 根列表打开独立工具时，明确继承本次 Launcher 唤起前捕获的外部目标，而不是把 Launcher 搜索框当作目标。继承保留原 X11 连接的窗口销毁监视，并给独立工具创建新的会话代际；原目标消失时不能改贴到当前碰巧聚焦的窗口。

若 Launcher 仍可见，用户转到另一个外部窗口后再次唤起，会重新确认该外部目标；无法确认进程或目标时清除旧值。普通内部编辑器入口不声明此继承意图，继续使用原有目标策略。此变化只作用于 Linux X11，未改变 macOS/Windows 的目标记录方式。

2026-10-09 的正式 Linux X11 构建中，以隔离配置和合成文本验证：从空白 Mousepad A 唤起 Launcher、打开历史并按单条 Enter，原 A 实际收到文本并恢复焦点；换新窗口 B 重走同一路径后，文本进入 B，A 未被追加。关闭已捕获的空白目标 C 后再执行，已检查的其他编辑窗口与 Launcher 查询均未收到该内容。随后手工粘贴到新空白页确认剪贴板保留了完整合成文本。目标销毁时未看到持续的复制降级提示，不能把防误投通过当作失败反馈已完善。macOS/Windows 与内部编辑器默认入口的兼容性依据代码和受控测试，本次未在这些环境实际操作。

验证入口：`npm run test:plugin-paste-behavior`；原生分类测试：`cargo test --manifest-path src-tauri/Cargo.toml --locked paste_availability_tests`。这些测试使用合成内容和受控 I/O，不代替真实系统权限、窗口焦点和目标应用验收。
