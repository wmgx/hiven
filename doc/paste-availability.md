# 自动粘贴可用性

自动粘贴前先查询当前原生宿主。查询不读取或写入剪贴板，不隐藏窗口，也不弹出权限申请。

- Linux 等没有粘贴模拟实现的平台：明确不支持。
- macOS：只读取现有辅助功能授权；未授权时提示去系统设置授权，或使用复制。
- Windows、已授权的 macOS：可以尝试，仍可能因目标应用、焦点或运行时权限变化失败。
- 旧原生宿主、无法连接或查询超时：状态未知，保留原来的执行路径。

已知不支持或缺少授权时，文本、图片和文件路径的粘贴 API 都在写入剪贴板、读取图片 blob、关闭窗口之前返回 `fallback: 'none'`。调用方保留当前内容，用户可以明确选择复制。Launcher 和工作流适配器会传播此失败，不能记录成成功交付。

Launcher 的文本结果和输入预览在实际提供自动粘贴目标时显示状态。打开目标条、重新聚焦或重新显示窗口会重新检查；真正执行仍重新查询。不能从插件权限声明推断操作系统已授权，也不能把一次查询当作粘贴成功保证。

如果已经开始真实粘贴并成功写入剪贴板，随后输入模拟失败，仍沿用原来的 `fallback: 'copied'` 行为。该情况与执行前拒绝不同；不能据此承诺已经关闭的窗口会恢复，或已发生的外部操作可撤销。

验证入口：`npm run test:plugin-paste-behavior`；原生分类测试：`cargo test --manifest-path src-tauri/Cargo.toml --locked paste_availability_tests`。这些测试使用合成内容和受控 I/O，不代替真实系统权限、窗口焦点和目标应用验收。
