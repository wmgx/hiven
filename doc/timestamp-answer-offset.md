# 时间戳即时答案保留偏移

时间戳搜索生成的日期时间现在同时显示并复制目标时刻的数字 UTC 偏移。偏移取自被转换的 Date，而不是当前日期，因此冬夏时和回拨重复小时可区分。非零毫秒仅在此即时答案路径保留，确保原时间戳精度不变；其他日期工具、默认时区和解析算法不变。插件版本更新为 1.10.1。

## 验证

隔离 Linux 原生 UI，系统时区保持 UTC：输入 `2026-01-01 00:30 +14:00`，复制毫秒时间戳 `1767177000000`；再次搜索，显示及复制 `2025-12-31 10:30:00+00:00`。通过真实键盘粘贴到外部 Mousepad，再全选复制，文本完全一致。将该文本重新搜索并复制，仍得到原时间戳。运行时释放目录的插件 manifest 确认为 1.10.1。

实际 provider、主复制及结果再次复制逻辑覆盖 UTC 跨年、非整小时偏移、非零毫秒、纽约冬夏时间和回拨时两个相同钟点。测试只修改测试进程的 TZ，不改系统时钟或时区。相关既有检查、类型检查、架构检查、前端及原生构建通过。其他平台及 DST 时区未做原生 UI 验证。

## 独立发现，未在本次修改

带显式偏移的日期文本重新解析仍先去掉偏移，再用宿主本地时区构建 Date。独立逻辑复现：纽约进程时区下 `2026-03-08 02:30:00+00:00` 被本地 DST 缺口归一化，结果为 `1772940600000`（03:30Z），而应为 `1772937000000`（02:30Z）。此问题位于既有 `parseDateForTimestampSuggestions`，未在真实纽约桌面 UI 复现，也不是本次显示改动引入；应另行修复显式偏移解析。
