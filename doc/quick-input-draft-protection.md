# 快捷文本输入的弃稿保护

原生复现：从搜索第一条 Base64 Decode 进入快捷输入，输入错误文本并预览失败，Esc 返回后再次进入时全文丢失；相同工具的 Workbench 则有弃稿确认。

本次在 Launcher controller 统一判断快捷文本输入的离开请求，Global Launcher 复用已有 ConfirmDialog 和中英文弃稿文案。Esc、返回、移除命令共享行为：精确全文相对本次初始值发生变化且尚未成功完成时，明确丢弃才退出；继续编辑保留原帧与错误。未改初值、还原初值、成功完成不额外阻塞。纯建议过滤、metadata 和已有独立材料编辑路径不扩大保护范围。带参数的内部返回仍保留输入，最后离开才检查。

第一次请求确认时使在途执行失效，迟到回执不能覆盖保留／退出后的页面；确认绑定原请求与帧，旧回调不能处置新访问。确认框默认继续编辑，Esc 取消确认；IME composing 事件不触发退出。焦点恢复避开打开的对话框，继续编辑回原输入。取消类输出动作不视为成功提交。

## 验收

隔离 Linux X11 原生 UI、仅合成文本：Base64 错误稿按 Esc 后显示确认，默认焦点在继续编辑；再次 Esc 关闭确认，全文、错误、焦点与选区 3–11 保留。命令标签 × 同样确认，继续后修正 Base64、预览并完整复制 SYNTHETIC 成功，无额外打断。共享 Remove Blank Lines 快捷输入验证返回按钮确认、明确丢弃回原搜索、重新进入为空；未编辑空稿直接返回。

在真实页面注入带 isComposing 的 Escape 事件，未触发离开；这验证事件边界，不等同于物理输入法候选窗的端到端验收。macOS、Windows 和物理 IME 未验证。

逻辑检查包含初值还原、参数往返、继续编辑、旧确认回调、取消输出不清稿、成功提交清洁、迟到错误无效；显式文本预览回归、类型／架构／差异检查、前端与原生构建通过。UI 验收还发现并修复会话层状态去重遗漏新增确认字段的问题。
