# 统一导航与系统设置页设计

> 日期：2026-07-01
> 状态：设计确认

## 背景

当前存在的问题：
1. 插件页和设置页缺少回退功能
2. 两个页面交互逻辑不统一（滚动、失焦关闭等行为不一致）
3. 回退与搜索栏的布局关系未定义

## 核心决策

### 1. 页面合并：插件页 + 设置页 → 系统设置页

将原本独立的「设置页」和「插件页」合并为一个统一的「系统设置」页面。

**内部结构：左侧 Tab 栏 + 右侧内容区**

```
左侧 Tab 栏：
┌──────────────┐
│ 基础设置      │  ← 原设置页内容，原样搬入
├──────────────┤
│ 插件管理      │  ← 原插件页内容，原样搬入
└──────────────┘

右侧内容区：
  选中哪个 Tab 就渲染对应内容
  内容区可滚动
```

**本质是容器层面的整合**，不涉及内容改造。

### 2. 系统头部栏升级：面包屑式导航

**现状：** 系统头部栏只有 `标题 + 关闭按钮`。

**改造为面包屑式：**

```
┌─────────────────────────────────────────────┐
│  ← hiven  /  系统设置  ×                      │
└─────────────────────────────────────────────┘
     ↑                ↑              ↑
  可点击回退       当前页面名       关闭按钮
```

| 元素 | 位置 | 行为 |
|------|------|------|
| ← hiven | 左侧 | 回到全局 Launcher，**保留 Launcher 之前的输入状态** |
| 系统设置 | 中部 | 当前页面标题，不可点击 |
| × | 右侧（紧跟页面名） | 直接关闭当前 surface，不经过 Launcher |

**适用范围：** 对所有 `rendersTitlebar: false` 的 plugin surface 生效。

### 3. Opt-out 机制不变

- 插件仍可通过 `rendersTitlebar: true` 自定义头部布局
- 剪贴板等已 opt-out 的插件不受影响
- 插件自己提供的独立面板（非设置类）是否保留，由插件开发者决定

### 4. Shell 配置

```ts
// 系统设置页的 shell 配置
shell: {
  closeOnBlur: false,     // 不因失焦关闭，必须手动关闭或回退
  rendersTitlebar: false, // 使用系统头部栏（面包屑式）
}
```

### 5. 入口与回退流程

```
用户唤起 Launcher → 输入 "Setting" → 回车进入系统设置页
                                              │
                              ┌────────────────┼────────────────┐
                              │                │                │
                          点击 ← hiven     页面内切换 Tab     点击 ×
                              │                │                │
                              ▼                ▼                ▼
                    回到 Launcher         停留在当前页面      关闭 surface
                  （保留输入 "Setting"）   （不影响回退栈）    （直接退出）
```

### 6. 页面内交互说明

- 左侧 Tab 切换不影响回退按钮行为（Tab 切换是页面内导航，不是页面跳转）
- 右侧内容区可滚动（修复现有滚动问题）
- 插件如果有自身设置项，通过打开系统设置页并定位到「插件管理」Tab 来处理

## 涉及的改动点

1. **系统头部栏组件** — 从 `标题 + 关闭` 改为 `← hiven / 页面名 ×` 面包屑式
2. **Launcher 状态保持** — 回退时恢复 Launcher 并保留输入状态
3. **新建系统设置 surface** — 合并原设置页和插件页内容，配置 `closeOnBlur: false`
4. **滚动修复** — 确保内容区可滚动
5. **移除旧入口** — 原独立的设置页和插件页入口指向新的系统设置页

## 设计原则

- **既开放又统一**：系统提供默认头部栏，插件可 opt-out 自定义
- **容器整合，内容不变**：不改造设置和插件管理的内容本身
- **极简头部栏**：只有回退和关闭，不放搜索框（设置页内有左侧 Tab 导航足够）
