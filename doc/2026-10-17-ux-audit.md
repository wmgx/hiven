## 一、最严重：核心承诺"输入即直答"在最常见的内容上失效

| # | 现象 | 证据 |
|---|---|---|
| 1 | **把 JSON 粘进 Launcher，显示"未找到操作"**，`{"a":1,"b":[1,2]}` 这种最简单的 JSON 也一样。必须先发现并点击右上角那个灰色小字"作为内容处理"。 | 实测截图；列表结果为 `未找到操作 / 试试更短的关键词，或清空输入`，这个提示还会误导用户去缩短 JSON |
| 2 | **格式化 JSON 要 5 步**：粘贴 → 点"作为内容处理"→ Enter → 选缩进（2/4）→ 选"排序键名 是/否"。缩进和排序本该有默认值、直接出结果。 | 实测流程 10→13 |
| 3 | 进入"作为内容处理"后，JSON 内容的候选列表里出现了**插件、设置、打开控制台、快捷编辑器、重启、关机**。内容动作和系统命令混在一起，而且危险操作就在 ⌘8 之后。 | 实测截图 11 |
| 4 | 空查询的默认列表把**重启这台电脑（⌘5）、关机（⌘6）、锁屏（⌘7）**排在前面，位置比任何文本工具都靠前。按错一个数字键就是关机。 | 实测截图 02 |
| 5 | 含 int64 大数的 JSON：格式化、压缩、排序会被直接拒绝；text-diff 会退回纯文本对比，格式化也不可用。字节的 logid、uid 等全是 int64。 | `src/kits/jsonNumberFidelity.ts`，`src/plugins/json-tools/jsonCore.ts:45` |

本质：Launcher 仍是"搜命令"模型，内容识别被藏到一个显式开关后面。真正做到直答的只有计算器（`1+2*3 = 7`）和时间戳（`1781064306 -> …`），这两个是好的范例。

## 二、交互冗余

1. **"未保存"确认铺满所有工具**：15 个工具接了 `host.setUnsavedChanges`，判定方式是"输入 ≠ 初始值"。只要打过一个字，按 Esc 就会弹"放弃当前修改？"。实测正则和翻译都弹了。这些是一次性的草稿工具，输入大多来自剪贴板，丢了的代价接近零。
2. **分支新增 71 个 confirm/unsaved/discard 类文案 key**。其中包括"历史保留期缩短前确认"、"窗口已有稿件，是否放弃并接收新内容"、"删除已保存工具的确认步骤"等。
3. **HUD 二段式**（翻译、二维码、Clean Agent）：第一次按快捷键只出一个被动预览，要**再按一次同一快捷键**才能看全文或复制；被动态 15 秒后消失。见 `doc/hud-translation.md`、`doc/qr-direct-hud.md`，以及文案 `hud.cleanAgent.hidden = 结果已就绪，再按一次快捷键后可查看`。
4. **curl 解析**的值默认隐藏，要点"查看原文"；页面顶部还写着"请在此工具内粘贴，**不要粘贴到启动器搜索中**"，等于让用户绕开核心入口。
5. **同一能力多个入口**：搜 `json` 有 21 条结果，比如"JSON 格式化"和"JSON 格式化工作台"并存；8 个"在 CSV Tools 中打开"、9 个"打开工作台中的对应功能"，副标题完全一样，没有区分度。
6. **副标题同义反复**："翻译 · 来自 翻译"、"JSON / YAML · 来自 JSON / YAML 工具"。
7. **搜索命中不准**：搜"剪贴板历史"后按 Enter，执行的是 `clipboard-history:open-image`（图片视图），不是主历史。依据是埋点 `item_select`。
8. **剪贴板历史一屏 67 个可见按钮**：筛选有 3 组（全部/收藏/常用/文本/图片/文件/回收区，时间段，全部词模式）；图片行显示的是 `image/png · 11 KB · 10月17日 02:21` 这样的元数据，没有缩略图。
9. **JSON 工作台**有两排 Tab（4 个模式加 5 个操作）和 6 个动作按钮。输入区标题栏上常驻"复制 JSONPath / 复制 JSON Pointer"，低频功能占了一级位置。

## 四、"自以为是"的设计

1. **大数拒绝处理**（见一·5）：用"拒绝"代替"做对"。
2. **敏感内容自动隐藏**：二维码、curl、HUD 基于启发式判断是否敏感并隐藏，用户要多一步才能看到。
3. **未保存守卫默认开启**（见二·1）：替用户判断"这段输入很重要"。
4. **AI 每次运行前强制重查 provider**（见五·1）：用户每次都为"安全"付出时延。
5. **Linux 优先**：约 1700 行 X11 专属代码，87 份文档以 Linux AppImage 验收，其中 30 份写明未验证 macOS。功能做在"开发 agent 能验证的平台"上，而不是用户实际在用的平台。

## 六、视觉与一致性（附带发现）

- "粘贴当前文本 / 复制当前文本 / 打开到快捷编辑器"没有配图标，退化成"粘 / 复 / 打"单字（`src/launcher/clipboard/actionRecommendation.ts`）。
- curl 解析工具是浅色、无样式的表单，其它工具是深色，风格割裂。
- Launcher 的"未找到操作"空状态卡片被窗口高度截掉一半（浏览器模式下观察到，需桌面端复核）。

## 改进方向建议（只列方向，不含实现）

1. **内容优先**：粘贴或输入的内容能识别出类型（JSON、时间戳、URL、Base64…）时，直接出结果卡片，Enter 复制或粘回原 App；不需要"作为内容处理"开关。
2. **参数有默认值**：格式化之类的操作直接用默认参数执行，想改再用 ⌘↵ 进参数页。
3. **系统命令降级**：重启、关机不进默认列表，也不进内容动作列表，只有明确搜索时才出现。
4. **删掉大部分确认**：只保留真正不可逆、且用户投入大的场景（例如删除已保存工具）。一次性工具的草稿直接丢弃。
5. **文案瘦身规则**：
   - 成功不提示，失败一句话说清"发生了什么 + 怎么办"；
   - 不写"已保留 / 未修改 / 不会…"；
   - 上限数字只在超限的那一刻出现；
   - 实现边界写进文档，不写进 UI。
6. **AI**：provider 的可用性用缓存，生成失败再刷新；不要每次运行前都检查一遍。
7. **大数**：做无损格式化，而不是拒绝。
8. **HUD**：一次快捷键直接显示结果，Enter 复制，Esc 关闭。
