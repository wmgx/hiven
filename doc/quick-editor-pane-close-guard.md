# Quick Editor 非空 pane 关闭保护

原先底栏关闭按钮与 Ctrl+W 直接删除 pane 的持久化正文；版本历史仅覆盖外部替换，不能恢复手工稿。现在所有 `closePane` / `closeActivePane` 调用统一经过确认：非空（含纯空白）只创建运行时请求，空 pane 直接关闭，最后一个 pane 不删除。

复用现有确认对话框，显示 pane 序号和首行预览，默认焦点为“继续编辑”。明确“关闭草稿”才删除。请求绑定稳定 pane id、正文修订号、完整文本和对象身份；重复快捷键不表示确认。修改后再改回同一文本、外部覆盖、历史恢复、切换 pane、新建 pane、重水合以及退出都会使旧请求失效。请求不持久化，也不增加关闭历史。

删除前核对当前持久化 pane 集合与顺序仍和本窗口一致，先成功写盘再发布内存状态；拒绝已落盘的其他窗口差异，写失败保稿。该检查不是跨窗口原子锁，不声称提供同时写入互斥。确认失败仍保留窗口并提示取消重进。原自动持久化、外部覆盖历史及整个窗口隐藏行为保留。

按钮按下不夺取原编辑焦点；取消由现有对话框恢复焦点，原 Monaco 选区不变。Esc 取消关闭确认，不触发快捷编辑器的二次 Esc 退出。组合输入时不启动本次快捷关闭路径。

验证：新关闭状态逻辑覆盖默认保留、取消与重复请求、版本 ABA、焦点变化、外部覆盖/恢复、已落盘跨窗差异、存储失败、空白内容和重水合。原外部覆盖回滚检查、快捷编辑器入口检查、类型、架构、前端及原生构建通过。独立审查已完成。

Linux 原生 AppImage / 新隔离 profile 的真实键盘流程通过：两 pane 分别输入完整合成稿；关闭 B 后 Enter 默认取消，连续 Ctrl+W 不确认，取消后复制原选区仍为同两字符；Ctrl+W → Esc 保留两稿；Ctrl+W → Shift+Tab → Enter 明确关闭 B，A 全文完整；返回 launcher 重进仍为 A；空 pane Ctrl+W 直接关闭；隐藏整个窗口不触发删除确认且保留 A。未读取真实稿件或使用真实 API。Windows/macOS、真实 IME 及跨窗口并发 UI 不在本轮实测范围，相关失效保护由逻辑检查和代码审查覆盖。
