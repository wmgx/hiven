# 结果操作的短标签与目的地

## 目标与范围

文本整理、编解码和格式工具的结果栏原有“转为输入”、两个仅图标的动作和复制。图标虽有辅助名称，用户仍需悬停才知道结果会留在当前工具、带回搜索或送到原应用。

本次保留原四个动作及顺序，显示“替换输入 / 带回搜索 / 粘贴 / 复制”；英文短标签为“To input / Search / Paste / Copy”。前三项低权重，复制沿用原背景和边框。JSON 保留其原有两个动作，没有补齐它未提供的输出目的地。命名转换列表仍用原图标，避免挤占各行结果。

完整目的地放在 title 和辅助名称中。替换输入的说明与实际行为一致：编解码切换到反向操作；JSON 的 YAML、查询串和字符串转换切到对应反向操作，表达式仍须手动执行；其他操作保留当前配置并重算。说明不增加常驻横条。

没有修改算法、参数、事件顺序、剪贴板或粘贴失败恢复合同，也没有新增菜单、动作或公共协议。

## 布局与验证范围

结果栏维持 44px 单行、原 11px 字号和预览区域高度，缩短标签并复用现有间距规则。代码中的独立工具窗口最小宽度为 640px（文本整理为 680px）；尺寸预算用于检查设计，不等于用户已能从 Launcher 拖动到该尺寸。

本轮实际 Launcher 原生窗口固定尺寸，系统窗口菜单的 Resize 不可用，因此不强改几何来冒充正常交互验收。代码 `5d4b740` 的实际中英文画面、键盘焦点与反向操作已在正常可达窗口上验证：URL/Formatter 为 884×664，文本整理为 924×684，JSON 为 884×684。

代码独立审查、最终 typecheck、架构边界检查、内置插件释放检查及前端构建通过。最终官方原生 AppImage 构建成功。URL 中英短标签保持单行，栏头与预览顶边和同尺寸基线一致；Tab 焦点完整可见，替换输入两次依次切换到解码和编码，结果带回搜索成为准确的新材料。文本整理与格式工具的四项、JSON 的原两项均有最终代表页实图，并经过独立设计复核。没有再次执行粘贴矩阵、收费 API 或全算法回归。640/680 最小声明宽度仅做了源码及字体尺寸预算，未作为正常原生拖动验收通过。
