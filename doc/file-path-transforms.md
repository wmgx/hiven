# 文件路径转换

`file-paths` 复用现有插件工具窗口与文本输入入口，提供 POSIX 分隔符、file URI、相对路径、纯文件名四种输出。一次处理一行一个路径，完整输出可显式复制；切换格式或转换失败不覆盖源文本。剪贴板写失败保留输入与输出，旧 owner / 输入变更后的迟到回执不显示成功。

## 来源与边界

当前公共插件 SDK 无读取文件管理器元数据或选择文件接口。现有原生命令 `read_clipboard_file_paths` 仅 macOS 实现，Linux / Windows 返回空数组，因此本版明确支持手动输入 / 粘贴路径文本，不宣称已经支持系统“复制文件”。没有合并文件分类实验、添加 Files 分类、读取文件内容或遍历目录。

路径转换为纯字符串处理，不检查路径存在性、不解析符号链接、不展开 `~` 或环境变量。相对路径必须明确输入绝对基准目录；不使用应用 CWD 或猜项目目录。跨盘符 / UNC 共享根禁止生成相对路径。Windows 路径比较忽略大小写，该规则并不检测大小写敏感目录。

自动模式识别 Windows 盘符与反斜线 UNC，其余按 Unix；以 `//server/share` 输入的 UNC 或 Windows 相对路径须显式选择 Windows。POSIX 模式仅改变分隔符，不把 Windows 盘符虚构为 Linux 挂载路径。file URI 按路径段编码 Unicode、空格、百分号、问号及井号；只接受 `file://`，不访问 URL。URI 的查询、片段及编码分隔符拒绝处理。

支持一行一条路径及末尾一个换行；保留名称中的前后空格，不把引号或 shell 转义自动剥去。路径本身含换行无法用该列表表达。上限为 1,048,576 字符、10,000 条路径、32,768 字符基准目录；超限明确失败、不截断。

## 验证

`node --experimental-strip-types scripts/test-file-paths.mts` 验证 Unix、Windows 盘符与 UNC、空格 / Unicode / URI 编码、显式相对基准与跨根错误、列表完整性和限制。逻辑检查不等于 Windows / macOS 实机验收。

已在隔离 Linux X11 原生 UI 显式粘贴含空格与中文的合成 Windows 路径，切换 file URI、相对路径、文件名，输入绝对基准目录并复制完整输出；系统剪贴板逐字核对通过。没有读取实际文件。
