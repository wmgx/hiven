# ChatGPT 登录链接交接

ChatGPT 通过本机 Codex App Server 建立登录。创建登录会话与浏览器成功显示页面是两件事：Linux 的系统打开程序可以先返回成功，再由桌面 helper 报告浏览器启动失败。因此设置页不再仅显示连接中的动画，而是保留明确的浏览器下一步。

## 当前登录会话

- 点击连接只创建一次会话；“再次打开”使用同一条链接，不重新发起登录。
- 链接与 loginId 仅保留在当前设置页面内存中。成功、取消、超时或关闭页面后清理；过时的异步回调不能恢复链接。
- 只接受官方 HTTPS 授权请求地址与明确允许的查询字段。令牌、密码、授权码等字段不允许用于链接交接。
- 打开失败只显示固定错误，不输出完整授权链接或底层错误载荷。此路径不调用可能把链接回显到标准错误的原生 fallback。

## 显式复制的保护范围

用户可以主动复制当前登录链接，在自己操作的浏览器中继续。应用不会自动复制、读取已有剪贴板或定时覆盖剪贴板。

登录链接不是 API Key，也不是访问令牌。本批在 Linux 上写入普通系统剪贴板，macOS 沿用系统敏感标记；其他平台的此专用复制暂时返回不支持。Hiven 在当前进程内标记这些链接，使其公开剪贴板读取接口不把链接交给历史或自动材料采集；标记不随登录取消或超时立即释放。其他剪贴板应用仍可能读取，应用重启后的保护也不作保证。通用密钥私密复制接口不会因此降级。

验证使用合成授权链接覆盖字段限制、同会话复用、取消与迟到结果、超时、固定错误和剪贴板读写边界。最终交互仍需在桌面检查按钮、反馈、取消返回和用户交接；模型推理、官网网络及用户登录成功不能由模拟测试推断。

## 本轮桌面验收

Linux 官方构建的实际界面已验证：一次 Connect 后显示等待登录说明，以及完整可见的重开、复制、取消三个按钮；一次 Cancel 后待登录区消失，Connect 和刷新恢复可用，并给出取消提示。此轮没有操作真实链接复制、输入账号凭据或发送生成请求；复制读写与竞态仅使用合成链接验证。

环境中还观察到两个独立阻碍：应用调用系统浏览器 helper 时返回启动 I/O 错误；普通终端虽可启动浏览器，公开主页随后显示连接被拒绝。后者不等于已经测试过具体授权端点。本批修复提供可理解的本地下一步，不宣称官网联网、账号认证或 ChatGPT 推理已通过。
