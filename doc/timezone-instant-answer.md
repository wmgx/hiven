# 搜索时区即时换算

日期时间插件在原搜索即时答案中支持 `3pm EST`、`2026-07-01 15:00 America/New_York`、`09:30 UTC+05:30`，输出北京／东京／UTC，一次回车复制完整结果，不打开新面板、不联网、不读取剪贴板。

- EST 明确为固定 UTC−05:00，全年不随夏令时变化。
- IANA 时区通过运行平台的 `Intl.DateTimeFormat` 解析，采用给定日期的时区规则。显示源时区和实际偏移。北京／东京目标同样使用 Asia/Shanghai／Asia/Tokyo 的日期规则，包含历史夏令时；历史秒级偏移保留秒精度。
- 省略日期时，采用**源时区当前日期**，显示实际所用日期；目标与源日期不同时显示 `+1d`／`-1d`（中文为天）。复制文本始终含源、目标完整日期。
- 接受 12 小时制 am/pm 或 24 小时制；显式日期格式 YYYY-MM-DD。CST／IST／EDT 等其他缩写拒绝猜测，提示使用明确 UTC 偏移或 IANA 标识。
- 夏令时跳过或重复的本地时刻都不擅自消歧，提示不存在或要求明确 UTC 偏移；无效输入不能复制错误结果。
- 既有 now／时间戳路径保持原行为。

逻辑验证：`TZ=Asia/Shanghai node scripts/test-date-time-assistant.mjs`。覆盖 EST 固定偏移、纽约冬夏时差、纽约与 Lord Howe 的跳过／重复时刻、源日期与跨日、半小时时区、无效日期和缩写、完整复制及原日期时间回归。真实原生 UI、插件释放版本及键盘／系统剪贴板由集成验证执行。

Linux 原生验收：EST 与纽约夏季日期即时答案及 Enter 完整复制通过；夏令时重复时刻明确拒绝。即时答案复用原搜索行，以答案、日期规则两行布局避免相互挤压，已核截图内容完整可见。
