详情表单替代方案对比

用于拍板两个界面局部的形态选择：插件设置弹窗里「多条目配置」的展现方式、插件列表行「展开抽屉」的信息密度。以下均为结构示意稿，配色为中性占位（暖灰底 / 墨黑主色），非最终视觉方案。

第一章 · 插件设置弹窗里「多条目配置」的三种形态

场景统一为「翻译 · 设置」弹窗（640×560）：顶部「默认设置」一行下拉；「API 配置」区含百度翻译、DeepL 两个条目，DeepL 展开后含基本（名称 / 服务商 / 启用）、凭据（Endpoint / AuthKey 掩码）、行为（目标语言 / 月度字符上限）三组字段。

方案 1 · 手风琴（现状）

条目本身是折叠卡：百度收起、DeepL 展开。卡头信息挤在一行，展开区把下面的条目和「添加」按钮顶下去，条目一多整个区域失控。

第二章 · 插件列表行「展开抽屉」的三种密度形态

场景统一为插件列表两行：翻译（展开态）、剪贴板历史（收起态）。行结构：32px 图标 + 名称 + 描述 + 「内置」tag + ⚠ 徽标（仅翻译）+ 键帽 + 开关 + ⚙ + ⋯。

方案 1 · 现状密版

抽屉里塞了元信息行、权限卡（名称 + 两行说明 + 敏感度标签 + 授权按钮）、已授权折叠行、快捷键区、能力 chip，信息密度过高，一屏放不下几个插件。
