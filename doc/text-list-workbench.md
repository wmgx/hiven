# 同一工作区整理名单

原有行排序、去重、反转、去空白、拼接、前后缀、包裹和 SQL IN 等 12 个行处理入口现在进入同一个文本工作台，并预选对应操作。输入和结果持续可见；选择操作只重新预览当前输入，只有点击“使用结果继续处理”才将当前结果作为下一步输入。

文本类增加“清理列表”，直接使用现有 cleanLineList：按用户选择依次去首尾空白、去空行、精确去重。默认参数保持现有清理工具合同（只去空行），没有新增处理算法或保存步骤的功能。JSON、URL 编解码与行处理可在同页切换。

旧 surface / command / tool ID、工具参数默认值和保存操作执行实现保持不变。命名比较、统计仍使用原展示；其行处理分支复用工作台，正文和初始修改基线由原外壳持有，不产生第二份草稿。切回命名/统计前后的操作及参数保留。复制、粘贴和带回沿现有结果身份、失败反馈、退出确认与异步撤销合同。

## 验证

定向逻辑覆盖实际 12 个 route 的组件映射、旧默认值/工具执行、保存操作回放、URL 解码→组合清理→排序→SQL IN、错误恢复与空结果；真实组件回调覆盖嵌入的单一修改标记、忙态切组与退出后的迟到回执。类型、架构和前端构建通过。

官方 Linux AppImage 构建通过（exit 0）。英文界面真实旅程使用一份合成 URL 编码名单：正常文件读入 48 字符，解码为 28 字符；显式继续后勾选三项组合清理，再继续、升序排序、继续、生成 SQL IN。整个处理过程没有返回根搜索，也没有使用剪贴板中转。最终输入为 alpha/beta/gamma 三行，结果为 24 字符 `('alpha','beta','gamma')`。点击复制后，在新 Mousepad 文档通过菜单粘贴确认全文精确一致。没有使用 Ctrl+V，也没有调用 AI 或处理用户数据。

正常搜索 `sort lines` 后，唯一旧入口直接打开新的工作台，Text / Sort Lines 和 Ascending 预选正确；空输入时结果交付禁用。此处不声明全部旧路由逐项桌面验收、中文 IME 或所有平台已验证。
