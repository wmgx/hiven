# 相对时间即时答案

在时间助手的原搜索即时答案中支持以下有限语法，不创建页面或任务、不使用 AI 和网络：

- 中文非负整数：`3天前`、`3日后`、`2小时后`、`15分钟前`。
- 英文：`3 days ago`、`in 3 hours`、`1 minute ago`（不区分英文大小写）。

结果显示完整绝对日期时间、UTC 偏移，说明基准时刻及系统 IANA 时区。基准精确到秒，以显示的基准计算结果，避免不可见毫秒导致复制后无法复算。回车完整复制输入、结果、时区、基准及计算规则；等待后仍复制这一明确显示的基准，不偷偷更新它。更换输入会重新取基准。Cron 的语义不同：它要求未来下次时刻，因此执行复制时重新计算。

「天／日」是日历天，保持当地时分秒，跨月按真实日历日期移动；不是固定 24 小时。「小时／分钟」是精确经过时长。目标日历时刻若落入 DST 空缺、重复时刻或跳过的民用日期，明确拒绝并提示改用精确小时；零天保持基准本身。月份和年份不支持，避免月末钳制／溢出策略的隐含猜测。

范围为最多 3660 天、87840 小时或 5270400 分钟。小数、负数、模糊量词和超范围输入明确提示；明确月份／年份输入提示不支持。不吞并现有时间戳、Cron 和时区换算查询。

纯模块测试 `node scripts/test-relative-time-answer.mjs` 覆盖双语语法、范围、闰日和月末、New York 日历天与 23/25 小时差别、DST gap/fold、Apia 跳过日期、Kathmandu 非整小时偏移。`TZ=Asia/Shanghai node scripts/test-date-time-assistant.mjs` 执行实际 dynamicItems 返回的复制动作，验证等待后复制基准不变、复制全文以及换输入后的结果更新。真实原生 UI 验收由集成者统一执行，模拟逻辑不替代 UI。

2026-10-11 原生验收：隔离 profile 中输入 `in 3 hours`，屏幕基准、UTC 时区和目标与 Enter 复制全文一致；`in 3 months` 明确提示不支持。DST 和日历边界通过固定时区逻辑验证，未把这些边界宣称为原生 UI 验收。
