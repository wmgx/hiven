# 单张图片裁剪

`encode-decode` 2.9.0 新增独立的「图片裁剪 / Crop image」搜索入口。专用面板只保留一个矩形，可拖选或输入源图像素 X、Y、宽、高，支持清除、显式复制 PNG 与原生另存。没有批量处理、旋转、压缩、遮盖撤销或新增宿主权限。

## 行为与边界

- 使用现有图片读取、方向归一化和大小限制。屏幕拖选按实际显示尺寸映射源像素，不乘设备像素比；反向拖选、边界约束与整数输入均得到验证。
- 拖选中的 Escape / 指针取消保留旧矩形。空、零尺寸、非整数或越界字段禁止导出。
- 导出建立选区尺寸的新画布，仅绘制源矩形，并编码扁平 PNG；原图、预览暗色蒙层及选区外像素不进入输出，没有可恢复图层。
- 新图成功读取才替换原图并清空选择。读取失败保留旧图与字段，需显式选择「保留当前图片」才恢复导出。未交付选区的替换和离开沿用确认保护。
- 操作序号、取消信号、宿主 owner 和即时状态共同拒绝过期结果与旧导出回调；操作完成和临时 blob 清理前保持重复操作门禁。取消离开后保留源画布，允许重试。已经完成的系统复制或保存不承诺撤回。

## 验收记录（Linux，2026-10-14）

使用隔离测试 profile、合成图片、Xvfb 桌面上的实际 Tauri/WebKit 应用和独立 GTK 粘贴接收器。未读取用户历史、未调用真实 API。实际加载插件版本 2.9.0。

真实界面通过：

- 1600×1000 合成透明网格在非整数显示缩放下反向拖选；精确输入 40、20、320、240；开始新拖选后 Escape，旧字段保持。
- 复制后在独立 GTK 程序 Ctrl+V，输出 320×240，重新解码后全部 RGBA 字节与源选区相同，包括全透明和半透明像素。
- 未保存修改返回时选择继续编辑，原图和矩形保持，再次复制成功。
- 原生另存对话框取消后重试，保存 PNG；独立 GTK 打开及像素检查通过，尺寸与 RGBA 字节完全匹配。
- 用损坏文件触发真实解码失败，旧字段保留且导出禁用；显式保留旧图后再次复制成功。文件样本通过 WebDriver 文件输入注入，未把这一步称为原生文件选择器验收。
- 最右下角 1×1 像素通过外部粘贴核验；零宽和清空选择均禁用导出。
- EXIF 方向 6 的 80×40 JPEG 读取为 40×80，导出的上红下蓝方向与预期一致。JPEG 只核方向、尺寸和颜色容差，不声称不同解码器逐字节一致。

独立逻辑验证：`scripts/test-image-crop.mjs` 使用受控画布检查矩形、精确输出尺寸、编码失败及取消；`scripts/test-image-crop-lifetime.mjs` 使用受控宿主检查晚回执、重复导出、离开失效、临时 blob 清理、替换失败和旧回调。它们不替代真实界面验收。

架构检查、前端构建和 Linux 原生 debug 构建通过。macOS Retina/WebView、macOS 原生复制与保存、macOS 图片方向行为尚未实机验证。未包含两个独立的未验证原生时钟/HUD 分支，也未发布或部署应用。
