# 清理行列表

在 Launcher 搜索“清理行列表”，使用当前文本材料或明确输入的文本，选择步骤后预览结果。只有点击复制或带回，结果才交付。交付成功后可用现有“保存操作”入口记住三个选项，供另一份文本重复使用。

处理顺序固定：每行首尾空白 → 空行 → 重复行。默认只删除空行，去首尾空白与去重均关闭。关闭全部选项时原字符串完全不变。

- 首尾空白使用 JavaScript `trim()` 的 Unicode 空白范围，不修改行内部内容。
- 空行包括只有空白的行，即使未开启首尾清理也会被删除。
- 去重针对前面步骤的结果精确比较，区分大小写，不做 Unicode 规范化，不排序，保留第一次出现。
- 每个保留行使用其原有 LF、CRLF 或 CR 分隔符；通常不统一混合换行；如果删除或清理使孤立 CR 与下一空行的 LF 紧邻，前者转为 CRLF，防止两次换行合并并吞掉空行。删行同时删除该行携带的分隔符。原文末行没有分隔符时，最后保留的行也不额外添加分隔符。
- 不删除空行时，首尾清理可把最后一行变为空。例如 `Ada\n  ` 只清理首尾得到 `Ada\n`。这保留了用户未要求删除的空行，不为末尾字符形式再偷偷删行。
- 全部行被删除时结果为空文本，由现有明确预览和交付流程处理。

实现位于 Text Tools 插件，未改已有单步算法、通用工作流或 SavedAction 数据格式。保存的是选中的步骤与原有输出方式，不保存输入正文。

关键回归入口：`npm run test:line-list-cleanup`。使用合成文本验证换行、大小写、全关闭/全删除、固定顺序，以及真实工具注册、参数预览、交付后保存和换材料回放。

## 桌面验收

官方 AppImage 已在 Linux Xfce 隔离配置使用合成名单完成：显式读取文本材料，核对默认步骤，开启三项后预览 `alpha`、`Beta`，带回并命名保存；换另一份材料回放，直接得到 `gamma`、`Delta` 的预览，带回后在材料编辑器确认正文。保存项显示三项参数及带回目标，回放不再逐项询问。预览、带回和保存没有自动复制结果。换行字节细节由算法回归验证，桌面验收只确认可见文本与操作流程。
