待拍板：快捷键列收尾 + 大小写转换族的图标

还没动代码

这两处不是 bug，是产品判断，所以先不动手：

① 第 9 项之后的"命令"标签——LauncherMixedList.tsx 里 ⌘1–⌘8 只覆盖前 8 行（QUICK_SELECT_MAX），第 9 行起用同一个视觉位置显示"分类标签"；「批量计算公式」「Base64 解码」 两个命令都没单独设置 display.kindLabel，于是都退回通用文案"命令"。视觉上它和前面的 ⌘ 键帽长得像，容易被读成"这里还能再打字触发"。可选方向：a) 给这两个命令补具体的分类文案（如"计算"「编码」）； b) 超出 8 个直接留空，不强行塞一个不提供信息的标签。

② 「大小写转换」整个命令族共用一个图标——variable-case/index.ts 里驼峰、帕斯卡、蛇形、常量、短横线等 11 个命令全部是 icon: 'CaseSensitive'。这个是合法的 lucide 图标（不是 bug），单看「PascalCase」一条没问题；但 11 个变体挤在同一列表里视觉上无法区分， 只能靠标题文字。截图只露出了其中一条，真要解决得看你是否认可"同族命令共享图标、靠分组/文字区分"这个方向， 还是想为每个变体做区分（例如用大小写示例文字如 aB/Ab/AB 代替统一图标）。

这两条都是"信息设计"判断，不是能靠代码单方面判定对错的 bug，所以先没直接改——按 [[hiven-visual-taste]] 的老规矩，涉及视觉/信息密度的取舍最好让你看效果挑，不读文字描述。等你回个方向（选 a/b，或者"两个都先不动"）， 我再落到代码。
代码改动：11 处图标引用修复 + 1 处图标去重 + 2 处运行按钮 className 精简，均已跑过 npm run build 和 npm run check:architecture（均通过），尚未 commit。 截图来源命令面板对应组件：src/components/launcher/LauncherMixedList.tsx（列表行）、 src/views/QuickEditorDetachedView.tsx / src/components/quickEditor/QuickEditorBreadcrumbActions.tsx（顶部工具栏）。
