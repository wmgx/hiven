# 搜索空动态结果的重复排序

## 已有证据

2026-10-10 在 Linux X11 隔离 QA 的 `2885e7a` 包中，进行一次正常隐藏、唤起和逐键输入合成查询 `json`。该旅程未观察到明显空白或旧窗口结果；截图采样不能排除瞬时闪现，也不是逐帧输入延迟测量。

现有埋点记录四个查询长度下的排序次数分别为 3、4、4、5 次，共 16 次。候选数始终为 131，各路动态结果均为空。同查询长度的结果数量一致。排序累计 227 ms，其中各查询首次排序之后的 12 次累计 115 ms；这些分散计算的累计值不是用户等待时长，也不是可承诺的节省量。首次必要排序的 65 ms 峰值不在本次修复范围。

## 最小改动

插件、宿主和文档三路结果仍保留各自的输入身份、取消和清空机制。仅将当前不可见或为空的动态列表映射到稳定空数组，使候选合并依赖实际可见列表。非空结果保留原数组和 item 对象引用；不按 systemKey 合并，不缓存排序结果，不改变排序规则或等待时间。

新查询、材料、设置、权限及真实非空结果变化仍应生效。相同 key 的新对象或新回调不得被旧对象替代。
