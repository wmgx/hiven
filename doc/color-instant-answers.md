# 颜色即时转换

`color-tools` 在原 Launcher 的即时结果中给出 RGB、HSL、OKLCH 三行，沿用原有上下键选择和 Enter 复制。没有新面板、窗口、全局快捷键或后台服务；搜索时不写剪贴板。每个结果同时显示完整颜色字符串、来源十六进制值及复制格式，色块只是辅助信息。

## 边界与精度

- 首版只识别完整 `#RGB`、`#RGBA`、`#RRGGBB`、`#RRGGBBAA`，可带前后空白。不将普通单词、CSS 表达式或搜索句子解释为颜色。
- 输入均为 sRGB 字节颜色。使用官方 [Color.js](https://colorjs.io/) 转换 HSL、OKLCH，不自建转换矩阵，不扩大到宽色域输入或隐式色域映射。
- RGB 保留原整数通道；HSL 保留最多 4 位小数，OKLCH 的亮度百分数/色度保留最多 6 位、色相最多 4 位。Alpha 最多 6 位，全部 256 个原始 alpha 字节能按四舍五入还原。全不透明时省略 alpha。
- 灰阶无效色相稳定显示为 0，色度为 0；输出没有 NaN 或负零。转换结果是经过说明的有限小数，不声称无限精度往返。
- 色块是已验证十六进制值生成的固定本地 SVG，透明色使用棋盘底。没有用户 CSS、脚本、外部资源或网络请求。读取颜色不需要剪贴板读权限，复制复用原宿主 `clipboard.write`。
- 复制失败由原 Launcher 错误状态处理，不报告成功、不关闭失败状态。

## 验证

`node scripts/test-color-answers.mjs` 验证严格输入范围、红/黑/白/灰转换参考值、透明度全部字节、恶意 CSS 拒绝及每次显式动作恰好一次模拟复制。只测试重要纯逻辑与交付边界，不测试样式，不调用真实 API。

已在隔离 Linux X11 原生应用中输入 `#FF6B35`，依次明确点击 RGB、HSL、OKLCH 三行，并读取系统剪贴板逐字核对完整结果。此项已通过。macOS / Windows 与键盘 Enter 路径未做本批实机验收。
