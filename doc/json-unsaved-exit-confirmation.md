# JSON 工作台主动离开确认

## 真实问题

2026-10-10，Linux X11 隔离 QA 的 `dbf6037` 包中，从无材料的搜索页打开 JSON / YAML 工作台。输入 61 字符有效合成 JSON，输出为 60 字符格式化结果。点击工具“返回”直接回搜索，再打开同入口，输入与输出均为 0 字符，没有丢弃提示。

这证明工具内新稿会在主动返回后重置；该路径原本没有挂载材料，不能将其描述为原文件或剪贴板历史丢失。

## 窄控制边界

插件只向当前宿主报告未保存改动的布尔状态。宿主不接收正文、不保存草稿，也不接受插件自定义否决离开的回调。

当前 Launcher 工作台中的主动 Back、Esc 和工具关闭使用同一确认：“继续编辑”保留当前挂载页面；“放弃”由宿主直接执行原导航。确认层内 Esc 只取消确认。成功复制完成和已确认的带回搜索交付沿原成功路径退出，不应再次询问。

JSON 将输入正文和表达式相对首次载入基线的变化视为改稿；自动格式化输出、操作模式、缩进和排序参数不单独触发。正文改回基线且表达式恢复初始值后，可直接离开。

此控制不承诺后台 5 分钟自动关闭、原生窗口销毁、外部强制替换或进程退出时保稿；不新增全局草稿持久化。
