# 图片按宽度缩小

`encode-decode` 2.10.0 增加可搜索的「图片按宽度缩小 / Shrink image by width」。复用现有图片页面外壳、显式文件／剪贴板读取及 PNG 复制／原生保存，不新增权限、顶层插件或编辑流程。

仅一个目标宽度输入，初始为原图宽度。接受不超过原宽的正整数，允许原尺寸；高度按原图比例四舍五入，未取整的比例高度不足 1 像素时拒绝。没有放大、百分比、自由宽高、批量、格式选项或目标 KB。PNG 不保证比原文件更小，缩小也不保证文字更清晰。

原图沿用既有方向归一化及输入限制：PNG/JPEG/WebP、10 MiB、单边 8192、16 Mi 像素。整图预览另限于 800×480 以内，并明确是原图预览。每次显式交付建立新画布，从原图完整重采样，不修改源图、不以之前的结果继续缩放；输出保留 alpha，PNG 超过 10 MiB 时完整失败，不截断、不暗改尺寸。

原图和输出两个 RGBA 缓冲上界约 128 MiB，另有预览、浏览器解码和编码开销；这不是进程内存硬限制。单次操作门禁保持到临时 blob 清理完毕，新图成功后释放旧图，导出 finally 释放输出画布，离开卸载释放保留图和预览。

无效输入禁止导出。换图／离开沿用未交付确认；失败保留原图和宽度，显式「保留当前图片」后恢复交付。取消保存、取消离开可重试。owner、修订号、取消信号和当前原图／宽度检查拒绝旧回执与旧回调；不承诺撤回已经发生的系统复制或保存。

## 验收（Linux，2026-10-14）

隔离 profile，合成图片，实际 Tauri/WebKit UI 与独立 GTK 接收器／查看器；未读取真实历史、调用真实 API 或修改历史记录设置。实际释放版本 2.10.0。

- 搜索打开，1600×1000 合成高频图改宽 800，外部 Ctrl+V 得到 800×500。四边彩色标记完整，透明块 alpha=0、半透明块 alpha=128。
- 再改宽 600，返回确认后继续编辑，外部粘贴得到 600×375。它与独立 WebKit 画布直接从原图缩小的参考 RGBA 一致，且与先缩到 800 再缩到 600 的参考不同，确认没有累计缩放。没有要求缩小结果与原图逐像素一致或与其他引擎一致。
- 原生另存取消后重试保存；独立解码尺寸／RGBA 与复制结果一致，并在独立 GTK 窗口重开。
- 零值、小数、超过原宽禁导出；取消替图保留宽度。损坏文件通过 WebDriver 文件输入触发真实解码失败，保留原图和宽度 400，显式 Keep 后复制恢复。原生导入选择器的自动路径选择未成功，本项不标为原生导入选择器验收。
- 8192×1 源图目标宽 1 因高度不足 1 被拒；32×20 小图目标 800 被拒，宽 16 输出 16×10 并保留 alpha=128。
- EXIF 方向 6 的 JPEG 规范化为 40×80，宽 20 导出 20×40，上红下蓝方向正确。
- 实际缩小桌面窗口后（WebView 664×417），复制／保存及导入按钮仍在可见区域。

独立逻辑与交互审查通过。必要受控逻辑覆盖尺寸、整图新画布、超限／编码失败／取消清理，以及晚 blob、leave/owner 变化、重复交付、失败恢复和旧回调；不冒充真实系统竞态。全量 TypeScript、架构检查、前端与 Linux 原生 debug 构建通过。

macOS WebKit 重采样外观、原生图片剪贴板和保存尚未实机验证。两个未验证原生专项分支保持隔离；未合并、发布或部署。
