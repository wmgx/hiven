# Hiven URL 学习规则交互设计

日期：2026-08-30  
状态：产品方案，未进入实现

## 1. 结论

采用“后台形成候选，Launcher 中确认后生效”的模型。

- 系统可以静默收集证据、生成候选，但 URL 候选不是规则，也不能自动执行。
- 候选只在与当前输入和来源上下文相关时，作为独立的“学习建议”出现；一次最多一条。
- 用户可以“试一次”，但试用不等于接受；只有“添加规则”或“编辑后添加”才创建可执行规则。
- 已接受规则才是正常搜索结果。拒绝、撤销、编辑和屏蔽都是附属动作，不进入结果列表，也不占快捷序号。
- URL 规则、候选、拒绝记录和生命周期全部归 `web-open`；host learner 不再保存或执行 URL-template。
- 浏览历史是“最近访问”，不是“学会规则”，独立召回和呈现。

这不是关闭自动学习。自动化被保留在证据收集、候选归纳、去重和排序上；把长期执行权留给用户。

## 2. 现状审计

### 2.1 当前流程

1. learner 根据输入形状生成 URL-template 候选。
2. 候选可能被 `web-open` sink 接收，也可能回退到 host IndexedDB。
3. host 通过 `learnedLauncherItems()` 把 URL 规则、历史召回和撤销动作转成同一种 `LauncherItem`。
4. `buildOpenUrlItem()` 和 `buildUndoItem()` 都是 `kind: dynamic`、`behavior: perform`、`directAnswer`。
5. 撤销项只靠比主规则低 1 的 priority 排在附近；模型中没有“它是上一条的附属动作”这一关系。

### 2.2 主要问题

- **意图证据不足**：`hex / uuid / id / slug` 只说明字符串形状相似，不能证明目标站点。
- **所有权重复**：插件 sink 和 host fallback 都能持有 URL 规则，清理一处后另一处仍可能恢复。
- **信息层级错误**：结果、建议、历史和反馈动作被压成一个扁平列表。
- **授权语义不对称**：执行被当成隐式接受，拒绝却要求用户执行另一条结果。
- **解释不足**：“新学的”“看过”没有说明来源、作用域、目标和后果。
- **管理语义过薄**：当前管理页只能删除规则或恢复 suppression，不能区分接受、撤销、拒绝、编辑和永久屏蔽。

### 2.3 审计证据边界

本次代码审计覆盖了学习存储、候选生成、fire、sink、Launcher item 和管理页。运行中的 Web Validation 页面因本地浏览器权限检查失败，未取得本次现场截图，因此本文不声称完成视觉或无障碍审计；视觉层级和键盘行为需在实现前用真实页面补验。

## 3. 产品对象与边界

### 3.1 四种对象

| 对象 | 含义 | 是否进入正常结果 | 是否占快捷序号 |
|---|---|---:|---:|
| 正常结果 | 手工规则、已接受规则、命令 | 是 | 是 |
| 学习建议 | 尚未获得执行权的 URL 候选 | 否，独立建议区 | 否 |
| 浏览记录 | 用户最近访问过的具体页面 | 是，历史分组 | 是 |
| 反馈动作 | 试用、接受、拒绝、撤销、编辑、屏蔽 | 否，附属于建议或规则 | 否 |

### 3.2 framework 与插件边界

Host / framework 只负责：

- 通用观察事件；
- Launcher 的结果容器、建议容器、焦点和键盘原语；
- 通用的附属动作与执行反馈；
- 不含 URL 语义的状态展示能力。

`web-open` 负责：

- URL 行为证据的消费；
- URL 候选归纳、安全筛选和冲突检测；
- URL 规则状态机；
- URL 建议的内容、文案、动作和管理页；
- URL 规则的唯一权威存储与执行；
- 浏览历史召回，但与规则学习分库存储、分组呈现。

Host learner 不再生成、保存、fire 或 fallback URL-template。插件不可用时，URL 学习不工作，不回退到 host。

## 4. 状态机

### 4.1 持久状态

| 状态 | 含义 | 可执行 | 自然衰减 |
|---|---|---:|---:|
| `candidate` 候选 | 后台证据达到门槛，尚未展示 | 否 | 是 |
| `pending` 待确认 | 当前上下文中可展示的建议 | 仅可试一次 | 是 |
| `active` 已接受 | 用户明确添加的规则 | 是 | 只降排序，不自动删除 |
| `rejected` 已拒绝 | 用户认为此精确候选不相关 | 否 | 否 |
| `revoked` 已撤销 | 用户撤销曾接受的规则 | 否 | 否 |
| `blocked` 永久屏蔽 | 用户屏蔽一个更宽的学习范围 | 否 | 否 |

`expired` 不需要持久化为业务状态：候选或待确认项过期后直接删除证据即可。

“试用中”也不需要持久化状态。`试一次` 是 `pending` 上的一次执行记录，不安装规则，不自动转正。

### 4.2 转移

```text
观察证据
  → candidate
  → pending（当前输入、来源和候选匹配）

pending
  → pending（试一次）
  → active（添加规则 / 编辑后添加）
  → rejected（不是这条）
  → blocked（永久屏蔽）
  → expired（14 天无新证据）

active
  → active（执行 / 编辑）
  → revoked（撤销规则）
  → blocked（永久屏蔽）

rejected / revoked / blocked
  → 仅在管理页手工恢复
```

### 4.3 撤销与拒绝

- 接受后的短时“撤销”回滚本次接受，恢复 `pending`，用于误点恢复。
- 管理页的“撤销规则”进入 `revoked`，不再触发，也不允许 learner 重新创建。
- “不是这条”进入 `rejected`，写入精确候选指纹。
- “永久屏蔽”进入 `blocked`。第一层只屏蔽精确模板；站点级屏蔽放在更多操作或管理页，并明确影响范围。
- 删除 active 规则不能只删规则记录，必须同时留下 suppression；否则下一轮会重新学回。

## 5. Launcher 交互

### 5.1 信息层级

```text
输入框

正常结果
  1  BOE Log
  2  Log CN
  3  最近访问：某条日志页面

学习建议（最多一条，不默认获得焦点）
  要记住这种打开方式吗？
  cloud.bytedance.net/log/{ID}
  仅当 ID 来自 cloud.bytedance.net
  [添加并打开] [试一次] [不是这条] […]
```

- 默认体验仍然是搜索和输入；建议永远排在正常结果之后。
- 建议不是 `LauncherItem`，不参与正常结果 ranking、计数和数字快捷键。
- 普通上下键只遍历正常结果；`Tab` 才进入建议区。
- `Enter` 在正常结果上按原语义执行；在建议动作上执行当前动作。
- `Esc` 从建议动作回到建议，再回到输入，不关闭前先恢复层级。
- 无正常结果时仍不自动接受建议；可以把焦点放到建议的“试一次”，但文案必须表明尚未保存。

### 5.2 建议卡必须解释的四件事

1. **学什么**：`输入 log {ID} → 打开 cloud.bytedance.net/log/{ID}`。
2. **为何出现**：`最近 14 天，你在 3 个不同会话中，从该站点复制不同 ID 后打开了同一路径。`
3. **何时生效**：`仅当 ID 来自 cloud.bytedance.net`，或 `仅输入“log {ID}”时`。
4. **动作后果**：`试一次不会保存；添加规则后，相同情境会作为正常结果出现。`

目标 host 和规范化路径模板必须完整可见。query、fragment、授权 token 和原始样本不展示；证据只显示脱敏形状、不同值数量、会话数和时间范围。

如果系统无法清楚说明来源、目标或触发范围，候选不应展示。

### 5.3 已接受规则

- 已接受规则与手工规则都属于“自定义规则”，不再显示“新学的”。
- 结果的附属菜单提供“为何出现”“编辑规则”“撤销规则”“永久屏蔽”。
- 编辑后的规则视为用户配置，learner 不得自动扩大范围、改目标或删除。
- 接受成功后显示非列表式反馈：`已添加规则：仅在……时打开……  撤销`。

### 5.4 浏览历史

- “看过”改为“最近访问”或“历史”。
- 历史项表示用户访问过具体 URL，不表示系统归纳出规则。
- 历史项没有接受、拒绝、撤销等规则动作。
- 同一 URL 同时命中已接受规则与历史时，保留规则结果，去掉重复历史项。

## 6. 动作定义

| 动作 | 结果 | 是否保存规则 | 是否阻止重学 |
|---|---|---:|---:|
| 试一次 | 打开当前推导 URL | 否 | 否 |
| 添加并打开 | 创建 active 并打开 | 是 | 不适用 |
| 编辑后添加 | 保存用户编辑后的 active | 是 | 不适用 |
| 不是这条 | 写入精确 rejected 指纹 | 否 | 是 |
| 短时撤销 | 回滚刚完成的接受/拒绝 | 按回滚结果 | 按回滚结果 |
| 撤销规则 | active → revoked | 保留治理记录 | 是 |
| 永久屏蔽 | 写入 blocked 范围 | 否 | 是 |
| 恢复 | 管理页解除 rejected/revoked/blocked | 视恢复目标 | 否 |

## 7. URL 候选的安全门槛

形状分类只能参与模板归纳，不能单独证明意图。自动候选必须同时满足：

1. 至少 3 个不同 token，跨至少 2 个独立会话。
2. 证据链是“明确来源上下文中的内容 → 打开同一 target host 与路径模板”。
3. 规则包含 `sourceHost` 或显式关键词；第一版不使用 `sourceApp`，待真实需求证明后再加。
4. 只支持 HTTPS、固定 host、固定路径前缀、单一变量槽。
5. 不自动学习 query、fragment、多槽位模板、localhost、IP、临时端口。
6. `auth / login / oauth / callback / checkout / session / token` 等敏感路径不进入自动候选。
7. 同一输入在当前上下文匹配多个目标时，不展示建议，也不执行；必须通过来源或关键词消歧。
8. 已有手工或 active 规则覆盖相同意图时，候选去重。

未绑定来源站点或显式关键词的裸通用 ID，不产生 URL 候选。全局裸 ID 匹配只能由用户手工配置。

候选身份使用：

```text
sourceHost + targetHost + normalizedPathTemplate + slotPosition + slotKind
```

这也是 exact rejection 的 suppression key，保证拒绝后不会换一个 clusterKey 重新出现。

## 8. 唯一权威存储

`web-open` 的规则库是唯一可执行事实源：

```text
WebOpenRule
  identity
  origin: manual | learned
  status: active | revoked
  matcher / scope
  targetTemplate
  evidenceSummary?       # 仅 learned
  createdAt / updatedAt

WebOpenCandidate
  identity
  status: candidate | pending
  evidenceSummary
  expiresAt

WebOpenSuppression
  identityOrScope
  kind: rejected | revoked | blocked
  createdAt
```

这不是要求新增三个数据库。第一版可复用 `web-open` 现有插件私有存储，以三类记录区分可执行规则、候选和 suppression。关键约束是：候选不能被 quick-open provider 当成规则执行，host 也没有 URL 副本。

## 9. 旧数据迁移

迁移必须一次性、幂等、失败可重试：

1. 保留没有 `auto` / `learnedFrom` 标记的手工规则，包括 BOE Log / Log CN。
2. 删除 `web-open` 旧自动 URL 规则。
3. 删除 host learner 的全部 URL-template 规则、导航证据和路径证据。
4. 对被清理的旧自动规则，能规范化出身份时写入 exact suppression，防止升级后立即重建。
5. 只有能证明用户明确编辑或确认过的旧规则才迁为 active；无法证明的一律不猜。
6. 永久移除 host URL candidate/fire 和 sink fallback；清理后不存在第二条恢复路径。
7. 所有步骤成功后才写迁移版本标记；部分失败时下次启动继续。

当前止血改动方向正确，但最终实现需要补上第 4、6 两点，不能把“一次清理”当成生命周期收敛。

## 10. 三种方案比较

**纯确认式**最安全：建议出现后直接要求添加或拒绝。缺点是每个有价值候选都多一次确认，容易重现旧提议卡的打扰感。

**静默试用式**让建议先执行几次再询问是否保留，摩擦更低，但 URL 打开已经是外部副作用；如果默认 Enter 就试用，用户仍可能把建议误认为结果。

**分层置信度式**能用来源、会话数和命中率控制建议排位，但不能让高置信度越过授权边界。数值分层还会扩大状态和调参成本。

最终采用三者的最小交集：后台静默形成候选，硬门槛决定是否展示；建议允许“试一次”；长期规则必须明确接受。第一版不做可见置信度分数、不做自动转正、不做通知中心、不做多建议并排。

## 11. 验收标准

- 输入未绑定来源或关键词的通用 ID，不生成任何自动 URL 候选。
- 同一查询最多一条学习建议；目标冲突时不建议。
- 学习建议与正常结果有独立容器、焦点模型和键盘路径。
- 拒绝、撤销、编辑和屏蔽不是同级结果，不占数字快捷序号。
- 建议一次交互内解释目标模板、证据、作用域和动作后果。
- `rejected / revoked / blocked` 都能阻止重新学习，且只能从管理页恢复。
- URL 规则只有 `web-open` 一个权威存储和一条 fire 路径。
- 历史召回使用“最近访问”语义，不使用学习标签或规则反馈动作。
- 迁移保留手工规则，清理两处旧自动规则，并留下可恢复的 suppression。
- 状态机和候选筛选使用最小可运行测试；UI 不写单元测试。
- 所有用户可见文案使用 `web-open` i18n。

## 12. 实施前需要确认的一项产品决策

建议区的默认动作推荐为“试一次”，不是“添加规则”。这能让用户先验证具体目标，同时避免一次执行被误解为长期授权。

需要产品确认：当正常结果为空时，`Enter` 是否可以触发“试一次”？推荐仍然不可以；让用户 `Tab` 进入建议后再执行，保持“结果”和“建议”的键盘语义稳定。

## 13. LauncherItem 完整视觉与交互规范

### 13.1 基础行保持稳定

所有正常结果继续使用同一行骨架：

```text
[28px 图标] [标题                     ] [类型标签 / 快捷序号 / 更多]
            [副标题或结果预览          ]
```

- 行高默认 56–60px，标题 13–14px，副标题 11–12px。
- 选中态使用完整的浅色背景，不使用彩色侧边条。
- 右侧最多同时出现一个语义标签和一个快捷序号；更多动作只在 hover、选中或键盘唤起时出现。
- 长 URL 单行省略；完整目标只在展开详情中显示。
- 图标表达对象或动作类型，标签表达来源或状态，两者不重复。

### 13.2 正常结果的四种呈现

| 类型 | 标题 | 副标题 | 右侧 | Enter |
|---|---|---|---|---|
| 普通动作 | 动作名称 | 参数或目标摘要 | 快捷序号 | 执行 |
| 即时结果 | 结果用途 | 结果预览 | `即时结果` | 复制或默认去向 |
| 历史结果 | 页面标题 | 具体 URL | `历史` | 打开具体页面 |
| 已接受规则 | `打开 {host}` | 生成后的具体 URL | `自定义规则` | 打开 URL |

不可用项保留在列表只用于解释缺失能力时：降低视觉权重、禁止 Enter，副标题说明恢复方式。纯粹无关的不可用项直接过滤，不占空间。

### 13.3 展开详情

正常结果保持紧凑；需要解释时，在选中行下方展开一个 detail region，不跳转新页面：

- 即时结果：展示完整输出及复制/切换去向。
- 历史结果：展示完整 URL、访问时间和移除历史动作。
- 已接受规则：展示作用域、来源和“为何出现”。
- 冲突项：展示冲突目标及建议的消歧方式，但不提供执行按钮。

展开详情属于当前行，不参与结果计数，也不接收数字快捷键。`→` 或 `Tab` 展开，`←` 或 `Esc` 收起。

### 13.4 学习建议不是 LauncherItem

学习建议使用 Launcher 的独立 supporting region，视觉上沿用相同字号、圆角和按钮，但不进入 `items[]`：

```text
正常结果列表
────────────
学习建议
  [建议摘要]
  [证据与作用域]
  [添加并打开] [试一次] [不是这条] […]
```

- 最多展示一条建议。
- 多个有效候选时只展示当前上下文最相关的一条，并显示“还有 N 条待处理”的次级入口。
- 多个候选争夺同一输入且无法消歧时，不选最高分猜测；改为冲突说明，提供“绑定关键词”或前往管理页。
- “集中处理”进入 web-open 的规则管理页，不在 Launcher 内展开候选瀑布流。

### 13.5 附属动作

复用现有 secondary action 语义，不把动作转换成新结果：

| 对象 | 主要动作 | 附属动作 |
|---|---|---|
| 普通动作 | 执行 | 固定、定制参数 |
| 即时结果 | 复制 | 切换去向 |
| 历史结果 | 打开 | 从历史移除 |
| 已接受规则 | 打开 | 为何出现、编辑、撤销、永久屏蔽 |
| 学习建议 | 添加并打开 | 试一次、不是这条、编辑后添加、永久屏蔽 |

鼠标通过行尾 `…` 打开附属动作；键盘通过 `Tab` 或 `→` 进入。危险动作不能成为默认焦点。

### 13.6 焦点模型

```text
输入框
  ↓
正常结果（↑ / ↓，数字快捷键，Enter 执行）
  Tab
当前结果附属动作
  Tab（到达列表末尾后）
学习建议
  Tab
建议动作
```

- 只要存在正常结果，初始焦点永远在第一条正常结果。
- 没有正常结果时，建议也不自动获得 Enter；用户必须 Tab 进入。
- IME composition 期间 Enter 只负责上屏，不触发结果或建议。
- 建议区、详情区和菜单都必须有可见 focus ring。
- `Esc` 按层级返回：关闭菜单 → 收起详情 → 回到输入 → 关闭 Launcher。

### 13.7 状态反馈

- 执行成功：Launcher 可按原行为关闭；需要连续操作时保留并显示短时状态。
- 试一次：`已试用一次，没有保存规则。`
- 接受：`已添加规则：以后仅在 {scope} 时出现。 撤销`
- 拒绝：`已拒绝，这条规则不会再次学习。 撤销`
- 撤销规则：从正常结果移除，并保留 suppression。
- 加载：结果区域使用稳定占位，不改变输入框位置。
- 错误：错误靠近触发动作显示；不能只用 toast，因为用户需要知道哪条 item 失败。

反馈动画不超过 150ms；`prefers-reduced-motion` 下直接切换状态。

### 13.8 响应式与窗口高度

- 窄窗口隐藏来源 pill，保留标题、目标和状态标签。
- 建议动作允许换行，但主要动作保持第一个。
- detail region 在窄窗口改为单列键值布局。
- 多个候选提示始终为单行摘要，不因窗口变窄展开成候选列表。
- Launcher 高度按内容增长到既有上限，超过后只滚动 body；输入框和 footer 固定。
